## Почему нельзя просто слить кэши

1. Native `operationInfos` хранит baseline API-ответ по recipe ID, без выбранной allocation и собственного времени наблюдения. Отсутствуют независимые ответы operation API для выбранных качеств. Native SavedVariables не содержат отдельного полного репозитория recipe schematics; конструктор получает схему через игровой API.
2. `dataSlotIndex` повторяется между фиксированными и quality reagents. Его нельзя использовать как единственный ключ при объединении слотов.
3. Native alchemy `equippedGear` в этом входе содержит пустые item slots, тогда как bridge и queue хранят конкретную экипировку. Это разные состояния/представления, не основание молча заменить один набор другим.
4. RecipeInfo `qualityItemIDs`, известный состав очереди и текущая установленная версия игры не подтверждают, что свойства старого персонажа актуальны сейчас.

Всё это допускает расчёт явного исторического сценария при достаточных входах. Оно запрещает только выдавать произвольное соединение таблиц за подтверждённый текущий расчёт.

## Требования к автоматическому вызову CraftSim, найденные в исходнике

Hashes точных установленных Lua-файлов записаны в JSON; наблюдения относятся к версии27.0.7.

| Участок | Подтверждённое поведение | Требование к адаптеру |
|---|---|---|
| `RecipeData.lua:2704`, `GetCraftingOperationInfoForRecipeCrafter` | Для другого персонажа/forceCache при отсутствии operation cache вызывается API текущего персонажа | Не присваивать такой результат другому персонажу; перед вызовом проверять происхождение/наличие кэша |
| `ReagentData.lua:390`, `GetSkillFromRequiredReagents` | При отсутствии baseline или selected operation API-ответа возвращается0 | Успешный `Update()` сам по себе не является доказательством полного расчёта; сохранять успешные ответы для конкретной allocation |
| `RecipeData.lua:2730`, `GetSpecializationDataForRecipeCrafter` | Есть возврат к cached specialization при слишком раннем пустом результате | Freshness нельзя устанавливать только по `specializationDataCached` |
| `RecipeData.lua:1257`, `GetSkillContributionMap` | Q1 получает вклад0 относительно Q1 baseline | Это не доказательство равенства пустого allocation и полного Q1 набора |
| `DB/CrafterDB.lua:200`, `SaveOperationInfoForRecipe` | Штатный API сохраняет operation info во внутренний кэш | Штатное сохранение CraftSim не следует путать с прямой записью приложением в чужой файл SavedVariables |

Полезный автоматический путь — использовать штатный движок при доступном контексте, сохранять точные входы и доказательства API по каждому сценарию в собственный аддон, затем считать и переоценивать эти сценарии вне игры. Для отсутствующих параметров нужен конкретный статус/причина, а не нулевое значение по умолчанию. Проверка реализации этого пути относится к отдельным тестам доработки, не к данному исследованию входов.
