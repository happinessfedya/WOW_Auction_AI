# Начни отсюда — пакет для двух Codex

Этот архив заменяет необходимость копировать длинные сообщения из чата. **Это не буквальный экспорт переписки**, а полный структурированный контекст и самостоятельные инструкции обоим Codex.

## Если ещё ничего не отправлял (основной сценарий)

1. Создай папку проекта, например `W:\VSProjects\WoW_Auction_Intelligence`, и открой её в VS Code с Codex.
2. Распакуй этот ZIP в подпапку `codex_handoff` внутри проекта. Получатся `codex_handoff/FULL_MAIN_PROMPT.md` и остальные файлы.
3. **Чат №1: Codex-разработчик.** Отправь: «Открой `codex_handoff/FULL_MAIN_PROMPT.md` и выполни всё указанное. Перед началом прочитай остальные документы `codex_handoff/`. Сейчас строго только этап 0; последующие этапы без моего разрешения не начинай». Это полный основной промпт, уже учитывающий дополнение о самоанализе экономической логики.
4. После завершения этапа 0 открой **отдельный чат №2: Codex-проверяльщик** в той же папке/репозитории. Отправь: «Прочитай `codex_handoff/INDEPENDENT_REVIEWER_PROMPT.md` и `codex_handoff/PROJECT_CONTEXT.md`. Проверь результаты этапа 0 основного Codex независимо и только на основании проверяемых фактов. Не изменяй рабочий код. Дай вердикт, доказательства и следующий промпт для разработчика».
5. Только если этап принят, отправляй разработчику команду на этап 1. Используй `STAGE_WORKFLOW.md` и `docs/implementation-plan.md`. Если отклонён — сначала исправление и повторная проверка.

Не пересылай разработчику только `MAIN_CODEX_CORRECTION.md`: он является *дополнением* к полному заданию. Если старт ещё не состоялся, пользуйся `FULL_MAIN_PROMPT.md`.

## Состав

- `FULL_MAIN_PROMPT.md` — **полное первое техническое задание основному Codex, этап 0**.
- `PROJECT_CONTEXT.md` — консолидированный контекст договорённостей и ограничений.
- `MAIN_CODEX_CORRECTION.md` — подробные обязательные уточнения об ошибках **экономической логики**, а не только Python-кода. Учтены в основном промпте; сохранять как подробный нормативный документ.
- `INDEPENDENT_REVIEWER_PROMPT.md` — самостоятельная роль второго Codex.
- `STAGE_WORKFLOW.md` — сообщения по принятию/отклонению этапов и контрольные риски.

## Правила безопасности

Не клади API-ключи, пароли, токены или реальные учётные данные в репозиторий/чат/отчёты. Не меняй файлы сторонних аддонов и не автоматизируй игровые сделки. Во время разработки прежде всего **виртуальная торговля**.
