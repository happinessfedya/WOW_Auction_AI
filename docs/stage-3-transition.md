## Уточнение автономности в ходе этапа 3

Пользователь прямо указал: приложение должно работать независимо от открытия конкретных рецептов, ручного CraftSim Scan и иных специальных действий в игре. Запрос ручной симуляции снят из обязательного процесса. Первые такие действия были диагностикой экспорта, но выявили архитектурный недостаток прежнего пути — локальные знания обновлялись только отдельной CLI-командой, а мост видел лишь открытый рецепт.

Исправление: автоматический `LocalKnowledgePoller` в обычном `knowledge-watch`, импорт уже существующих CraftSim/TSM кэшей, автоматическое определение установленного build и пассивный мост с отдельным пакетом доступных механических данных. Полный каталог/рынок и обработка сохранённых сведений работают при закрытой игре. Новые сведения из игрового API могут появиться только во время работы клиента; отсутствие контекста — unknown, не требование пользователю вручную заполнить профиль. Готовый расчёт открытого рецепта остаётся дополнительным наблюдением. [Доказательства и граница автономности](research/stage-3-autonomy.md).

Полный новый персональный расчёт CraftSim из произвольного неполного кэша не объявляется реализованным. Его публичный конструктор зависит от игрового контекста и обновляет внутренние базы CraftSim; подтверждённого полностью читающего batch-режима не найдено. Прямая запись в чужие SavedVariables, управление игровым интерфейсом и автоматические игровые действия не добавляются ради обхода этого ограничения. Это явно оставшийся технический пробел, а не скрытая ручная зависимость запуска приложения.
