# Этап 3: запуск и воспроизведение

Все команды из корня проекта. Данные хранятся в `.private/`; существующие базы активов и рынка не заменяются. Blizzard credentials не нужны. `knowledge-status` не требует интернета или игры.

Обычная работа не требует открытия рецептов или запуска сканирования CraftSim. После настройки локальных источников на этапе 1 достаточно запустить процесс:

```powershell
.venv/Scripts/python.exe -B -m wow_auction knowledge-watch
```

Он автоматически читает изменившиеся TSM/CraftSim/собственный экспорт, использует сохранённые рецепты/операции, обнаруживает установленный build по `.build.info`, ставит недельные и патчевые обновления. Уже сохранённые сведения доступны при закрытой игре. При отсутствии данных выводится ограничение, другие источники продолжают работать. Для одноразовой локальной проверки без сети: `knowledge-local-scan`. Процесс не установлен как служба автозапуска Windows; он работает, пока запущен. Монитор рынка этапа 2 остаётся отдельным процессом `market-watch`.

Обязательный ручной шаг с выбором реагентов снят после уточнения пользователя. Далее приведены способы воспроизведения и **необязательные диагностические команды**, а не пользовательский сценарий ежедневной работы. Граница автоматически доступных данных описана в [протоколе автономности](research/stage-3-autonomy.md).

```powershell
.venv/Scripts/python.exe -B -m wow_auction knowledge-status
.venv/Scripts/python.exe -B -m unittest discover -s tests
```

Первый полный импорт: загрузчик получает закреплённый ATT commit `3d0461d9740940e09c9cb19390467ed6ec39cb9c`, все выбранные author Lua/config/shared и LICENSE. Повтор использует только файлы с совпавшими Git blob hashes. `.wago/` и ARR-таблицы TSM перечислены как blocked, не импортируются под чужой лицензией. Загрузка требует сети и может занять несколько минут.

```powershell
.venv/Scripts/python.exe -B -m wow_auction knowledge-update --build 12.1.5.70575
.venv/Scripts/python.exe -B -m wow_auction knowledge-candidates att-standard --limit 10
```

Для уже скачанного корпуса исследовательского запуска:

```powershell
.venv/Scripts/python.exe -B -m wow_auction knowledge-scan .private/stage3/corpora-att --revision 3d0461d9740940e09c9cb19390467ed6ec39cb9c --build 12.1.5.70575
```

Рабочий каталог обновляется раз в неделю; смена переданного build ставит внеочередное задание. `--force` запрашивает проверку сейчас. Последний commit сначала разрешается через публичный GitHub, затем все запросы закреплены за его SHA. Новая неизвестная ветка не исключается из обхода по словарю семейств. При сбое остаётся последняя завершённая версия; причина и retry отражены в статусе. Пока процесс не запущен, автоматических опросов нет. Build следует брать из своей установленной игры; эта команда не проверяет наличие профессии на персонаже.

```powershell
.venv/Scripts/python.exe -B -m wow_auction knowledge-update --build 12.1.5.70575 --force
.venv/Scripts/python.exe -B -m wow_auction knowledge-watch --build 12.1.5.70575 --interval 60
```

`Ctrl+C` останавливает процесс. После перезапуска истёкшие leases можно забрать заново. Задания `candidate_research`/`feedback_research` здесь не расходуют токены и не считаются выполненными; облачный исследователь относится к этапу 6.

Для ручного отката каталога используйте ID из `knowledge-status`:

```powershell
.venv/Scripts/python.exe -B -m wow_auction knowledge-rollback att-standard 1 --reason "Причина из независимого заключения"
```

`knowledge-feedback SOURCE KEY MESSAGE` только ставит исследование в очередь. `knowledge-propose FILE.json` сохраняет предложение (`source_id`, `key`, `candidate`, `evidence`, `reason`); нужны два разных upstream, hash/reference/build/current/observed_at. `knowledge-review SOURCE KEY ID --review-reference REF --reason REASON` записывает состоявшееся независимое решение. ID=0 снимает наложение. Эти команды не выполняют проверку истинности источников вместо проверяющего и не делают candidate торговой рекомендацией.

## CraftSim и предметы

Мост находится в `addons/WowAuctionBridge`. Его протокол, точные ограничения и воспроизведение Lua-проверок описаны в [исследовании](research/stage-3-craftsim.md). Мост не создаёт крафт, не выбирает реагенты, не делает reload и не меняет чужие SavedVariables. Для REAL-проверки пользователь вручную открывает доступный рецепт с CraftSim, ждёт расчёта и вручную сохраняет интерфейс через `/reload` либо обычный выход. Покупать или создавать предмет специально не нужно. До реального файла проверка игрового события/сохранения остаётся OPEN.

Фактический прогресс: пользователь подтвердил появление моста после **полного перезапуска WoW**, затем выполнил сканирование и ручные сохранения. Версия 0.3.0 дала четыре ошибки capture; после обновления собственной папки до 0.3.1 два новых DTO сохранились без ошибок. Это подтверждает путь event→собственный SV→Python, но не полную положительную сверку профиля. Для нового аддона может потребоваться полный перезапуск игры; для обновления уже обнаруженного моста достаточно загрузить обновление ручным `/reload`. [Первый REAL capture](research/stage-3-craftsim-real-initial-evidence.json), [второй capture и сверка с источником](research/stage-3-craftsim-real-second-evidence.json).

Массовый scan не равен экспорту всех его результатов: текущий мост наблюдает `GetOpenRecipeData` по ready-событию открытого рецепта. Полный фиксированный профиль требует распределённых количеств качественных реагентов; выбор в режиме симуляции не расходует предметы. CraftSim умеет подставить самые дешёвые качества при незаполненных слотах; такая стоимость сохраняется как результат движка, но не выдаётся за выбранный игроком точный набор.

После появления собственного `WowAuctionBridge.lua`:

```powershell
.venv/Scripts/python.exe -B -m wow_auction knowledge-craftsim "ПОЛНЫЙ_ПУТЬ_К_WowAuctionBridge.lua" --build 12.1.5.70575
.venv/Scripts/python.exe -B -m wow_auction knowledge-items "ПОЛНЫЙ_ПУТЬ_К_TradeSkillMaster.lua" --build 12.1.5.70575
```

Обе команды дважды стабильно читают файл, не исполняют Lua. CraftSim fingerprints включают параметры крафтера, качество, реагенты, gear/spec/buffs, concentration, overrides, prices, build. Отсутствие необходимого поля или устаревший контекст дают `missing_data`/`unsupported`/`stale`. Переоценка фиксированного варианта — модельное ожидание, не новый игровой расчёт, не гарантия продажи и не PMF целочисленных исходов.

Повтор одного файла при той же версии нормализатора и build возвращает `artifact_unchanged`: первый payload и время получения неизменны. `profile_statuses_now` отдельно оценивает свежесть сейчас. После исправления адаптера создаётся новая нормализация того же raw hash, старая сохраняется. `capture_status` описывает полноту сохранённых фактов, `context_status` — актуальность контекста персонажа; перезапуск не делает исторические факты ложными и не доказывает неизменность текущего персонажа.

TSM item cache содержит сведения о шаблоне предмета, а не о фактическом binding экземпляра. Импорт метаданных не меняет автоматически статусы запасов/капитала. Общий статус показывает количества, без имён персонажей и денежных остатков. Сами локальные артефакты могут содержать личные игровые данные; они исключены из Git.

Перед следующим этапом обязательно снова прочитать [реестр аудитора](reviews/open-verifications.md) и сопоставить с новыми доступными данными. [Доказательства этого перехода](research/stage-3-prior-verifications.md) не заменяют независимый вердикт.
