## S1-01 — контекст источника и повторный учёт

Причина подтверждена: изменение региона меняло fingerprints, а ветка отсутствующих
семейств сохраняла строки прежнего региона как вторую действующую книгу.

Добавлен [ledger_context.py](../../wow_auction/ledger_context.py); переход контекста
отделён от обычного отсутствующего семейства в [storage.py](../../wow_auction/storage.py).
Решения:

- При уточнении `None → region` только для тех же bytes, той же группы источника
  и совпадающего набора нормализованных наблюдений исправляется контекст той же
  записи. Canonical ID, количество и high-water сохраняются, ревизия увеличивается,
  финансовое событие не выпускается. Это доказанная повторная интерпретация
  одного файла, а не поиск похожей сделки в другом регионе.
- Смена известного региона, одновременная смена bytes/контекста или смешанный
  старый state дают `requires_resolution`. В текущей проекции только новые
  наблюдения с `row_state=context_conflict`, `uncertain=true`; второй подтверждённой
  книги и новых финансовых приращений нет. Возврат настройки не снимает конфликт.
- Проверка смешанного legacy-state выполняется до shortcut `unchanged`.
  Частично отсутствующее CSV-семейство в прежнем контексте продолжает сохранять
  старые наблюдения и не выдаётся за удаление сделок.
- Для уже повреждённой книги есть явная команда `rebuild-ledger-context` с новым
  backup и обязательным основанием. Она заново читает только сохранённые raw
  snapshots этого источника в явно выбранном контексте. До записи проверяется,
  что после backup другая транзакция не изменила книгу. Восстановление проекции,
  запись решения, отметки ручных связей и checkpoint атомарны.
- Старые snapshots и `ledger_changes` не удаляются. Решение сохраняет границу
  предыдущих пакетов изменений и hash backup. Представление
  `effective_ledger_changes` показывает только действующий период учёта;
  восстановленный baseline не является новой сделкой. Нельзя суммировать весь
  исторический `ledger_changes` после такого исправления как текущий финансовый
  поток: старые ошибочные приращения оставлены для аудита.

Утверждение, что вся история одного источника относится к выбранному региону,
при спорной смене — явное локальное решение пользователя, записанное с причиной.
Если это действительно разные региональные источники, они подключаются раздельно;
автоматического слияния нет. Raw replay сохраняет обнаруженную неопределённость
уменьшений/неоднозначных агрегатов; исправление контекста не очищает её по догадке.

Регрессии: [pure context tests](../../tests/test_ledger_context.py),
[интеграция Store/CLI](../../tests/test_review_storage.py): None→EU, EU→US,
возврат/повтор, загрязнённая проекция, неизменность истории, восстановление,
резервная копия и rollback. Ручные связи проверены совместно с S1-03.

## S1-02 — ограниченная конвертация чисел BagSync

Причина подтверждена: `int()` над 5000-значным item ID/quantity выбрасывал
недоменный ValueError до регистрации карантина.

В [assets.py](../../wow_auction/assets.py) перед конвертацией проверяются
1–19 ASCII decimal digits и диапазон signed 64-bit, согласованный с прежним
контрактом `_integer`. Ноль запрещён там, где требуется положительное значение.
Та же проверка применяется к expiry в `auction` option. Это техническая граница
представления, не ограничение торговли. Непрозрачные неизвестные options
сохраняются без попытки превращать их в числа.

Ожидаемый отказ становится безопасным `AssetSchemaError`; глобальный лимит
Python не увеличен, catch-all не добавлен. Обычный импорт регистрирует карантин,
сохраняет last good и продолжает остальные источники.
[Регрессии](../../tests/test_numeric_quarantine.py) запускают настоящие scan/watch
для обоих примеров аудитора, проверяют отсутствие traceback/приватной строки,
соседний expiry, превышение диапазона и не-ASCII цифры.

## S1-03 — действительность ручных связей

Причина подтверждена: проверка количества была только при создании overlay,
последующий импорт не проверял зависимые распределения.

[manual_links.py](../../wow_auction/manual_links.py) добавляет неизменяемую привязку
решения к endpoint revisions/scope и историю его проверок/отзыва. Миграция 3
добавляет таблицы без изменения checksum миграций 1–2 и без удаления старых связей.
Связь legacy без подтверждённой привязки требует пересмотра.

- При изменении ревизии/контекста, missing/uncertain endpoint или превышении
  совокупного количества связь получает `requires_review`, confirmed quantity=0.
  Даже прежнее увеличение количества требует нового подтверждения ручного
  решения; это консервативная проверка его основания, не отмена покупки.
- Неопределённость остаётся до явного supersede или отзыва. Возврат CSV к прежнему
  виду и повторный импорт не подтверждают решение автоматически и не плодят
  одинаковые проверки.
- Исходное количество связи не обрезается. Новая редакция — отдельная запись;
  `unlink` добавляет отзыв с причиной, не удаляет исходную связь/историю.
- Обычный status показывает счётчики состояний, `--details` — причины и историю
  локально. Персональные поля/заметки не добавлены в стандартную диагностику.

Регрессии: [модуль связей](../../tests/test_manual_links.py) и
[сквозные проверки](../../tests/test_review_storage.py): quantity decrease,
ambiguous matching, missing, смена scope, повтор, aggregate allocations,
legacy migration, supersede/revoke и совместный переход контекста.
Полная себестоимость/P&L не реализовывалась; unknown не заменён нулём.
