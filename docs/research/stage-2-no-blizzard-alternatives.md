Дата исследования: **26.10.2026**. Последняя сверка локальных исходников и времени: **10:46 UTC / 13:46 МСК**. Документ подготовлен разработчиком для независимой проверки; это не заключение аудитора и не заявление о завершении этапа 2.

Последующая техническая ревизия по отрицательному R1: [ответ S2-01–04](../review-responses/stage-2-r1-response.md).

## 1. Обязательное ограничение и область отчёта

Пользователь прямо запретил получать и использовать Blizzard client ID/client secret, проходить регистрацию API/Authenticator и включать рабочее подключение к Blizzard API. Запрет действует также для optional-настроек, резервного источника, автоматического fallback и фонового worker. Недоступность другого источника не разрешает повторно предлагать этот маршрут. Исторические документы о Blizzard сохраняют значение исследовательских свидетельств, но больше не задают рабочую зависимость проекта.

Здесь сопоставлены все наборы, для которых прежний план предполагал Blizzard: realm index/detail, connected-realm index/detail, commodity/realm offers, item metadata, profession index/detail, skill tiers, recipes. Дополнительно рассмотрены варианты предметов, история, глобальный каталог преобразований и build. Прежний перечень методов находится в [M08](market-sources.md#m08-blizzard-game-data-официальные-контракты); изменение общей архитектуры и плана оформляется отдельно.

На этом исследовании выполнялись только чтение публичной документации и локальных данных/исходников. Blizzard API/OAuth не вызывались, credentials не искались, WoW не управлялся, игровые действия не выполнялись. Реализация экспортёра, парсера каталога и расчёта CraftSim относится к этапу 3 и здесь не начиналась. Рассмотрение уже предусмотренного экспортёра из аддона не означает разрешение на его запуск сейчас и не возвращает внешний Blizzard API в приложение.

**Вывод:** независимость от Blizzard credentials достижима. Равенство возможностей прежнему плану не доказано: сейчас доступны реальные статистики TSM и локальные кэши; данные глубины/истории UE имеют отдельный блокер условий использования; полный глобальный каталог требует будущего обхода альтернативных корпусов с явными пробелами.

## 2. Статусы доказательств

| Метка | Значение |
|---|---|
| **REAL** | Прочитаны реальные данные или установленный исходник. Для исходника это доказательство структуры/алгоритма, не успешного выполнения в игре. |
| **DOC** | Владелец источника публикует соответствующую документацию/условия. Ответ рабочего API этим не подтверждён. |
| **PLAN** | Проектное решение или будущая реализация, обоснованные перечисленными свидетельствами. |
| **UNKNOWN** | Не установлены данные, полнота, актуальность, семантика либо права. Такой статус не превращается в пустой подтверждённый результат. |

Отдельно различаются **доступность источника**, **права конкретного использования**, **свежесть**, **полнота** и **пригодность для экономического решения**. Один успешный HTTP200 не заменяет остальные проверки.

**DOC:** [Terms of Service](https://undermine.exchange/terms.html), редакция 30.04.2026: §2 разрешает личное некоммерческое получение доступного content при соблюдении остальных условий; §3(5) ограничивает автоматизированный доступ; §7 ограничивает систематический сбор базы без письменного разрешения, automated gathering и обход ограничений. В начале Terms дополнительные документы включаются по ссылке. Эти положения прочитаны 26.10.2026.

**UNKNOWN — трактовка:** API может подразумевать специальное исключение, но явное согласование этого исключения с общими запретами, локальным накоплением history, retention и передачей производных данных не найдено. Нельзя молча принять ни «API отменяет Terms», ни «владелец запретил любое предусмотренное API использование» за доказанный вывод.

**PLAN/действующая защитная настройка:** до разрешения противоречия `network_allowed=false`, retention 0, статус `unresolved_api_terms_conflict`; ключ, доступность бесплатного метода и оплата не снимают блокер. Проверяемый факт реализации политики находится в [market_policy.py](../../wow_auction/market_policy.py); этот документ не утверждает, что все связанные runtime-проверки уже приняты аудитором.

Достаточное основание пересмотра — явное действующее уточнение владельца/API-specific terms для нужных действий и обновлённая версия SourcePolicy. Письма, регистрации и покупки этим исследованием не разрешены и не выполнялись. До пересмотра UE остаётся сравнительным кандидатом, а не работающим fallback. Нельзя подменять API сбором внутренних бинарных файлов сайта или обходить 403/платные возможности.

### 5.2. TSM: рабочий публичный путь с ограниченным использованием

**DOC:** [Public Pricing Data](https://tradeskillmaster.com/public-data) прямо описывает импорт публичных CSV в пользовательские инструменты без ключа/входа. Обновление realm/commodities — каждые несколько часов, region — ежедневно; `updatedAt` отражает upstream scan. **REAL:** три настоящих CSV были успешно прочитаны в M05. Эти факты обосновывают текущую личную рабочую интеграцию.

[TSM Terms](https://tradeskillmaster.com/terms) сохраняют права на оригинальное содержание и не гарантируют полноту/точность. **UNKNOWN:** явное разрешение бессрочного архива, массовой перепубликации или отправки всего массива облачному сервису не установлено. Четырёхчасовой рабочий кэш в текущей SourcePolicy — **выбранное проектом ограничение**, а не заявленный владельцем срок лицензии или доказанная юридическая гарантия. Срок и режим фиксируются отдельно от частоты обновления источника.

Локальный AppHelper является дополнительным уже установленным каналом статистик; он не даёт автоматически больше прав или полную книгу лотов. В [L14](local-addons.md) зафиксированы его формат и часы. Использовать `loadstring` внешнему приложению недопустимо; безопасный разбор и проверки версии — отдельная работа.

Конкретные ревизии и конфликт артефактов задокументированы в [D2-01–D2-06](transformation-discovery-r2.md#1-факты-и-воспроизводимые-свидетельства).

Отдельно учитываются три слоя:

1. Авторские ATT Lua claims, constructors, filters и связи — собственный pinned corpus и лицензия.
2. Импортированные `.config/.wago/...csv` — provenance Wago/Blizzard, build, download/hotfix mode, hash и преобразования cleaner. Права и полнота не наследуются из имени родительского репозитория.
3. WoWDBDefs — схемы таблиц. [Его лицензия](https://github.com/wowdev/WoWDBDefs/blob/master/LICENSE.md) различает CC BY-SA 4.0 для definitions и BSD-3-Clause для code; она не превращает описание layout в сами игровые данные или разрешение на их публикацию.

**REAL из R2:** ItemXItemEffect и ItemEffect содержат соответственно 60 644 и 62 149 строк опубликованного зеркала; это связи item/effect/spell, не полная модель преобразования. **REAL исходник:** ATT cleaner для SpellEffect использует allowlist эффектов. Поэтому его результат заведомо не полный универсальный create-item/reagent/loot dataset. Успешная загрузка этого файла не устранит семантическую фильтрацию.

**UNKNOWN/BLOCKED:** повторное web-открытие [wago.tools](https://wago.tools/) вернуло 403. Это результат доступа через инструмент, не доказательство отсутствия сервиса. Подтверждённого разрешённого bulk export с условиями reuse не получено. [Wago.io Terms](https://wago.io/terms-of-service) описывают другой сервис; их нельзя автоматически объявить применимыми к wago.tools. По этой причине массовый Wago импорт не становится готовой заменой по одному URL из ATT batch script.

## 6. Режимы работы и существенные решения

| Режим | Доступно / возможно | Что явно отсутствует |
|---|---|---|
| **Без Blizzard; текущая политика UE закрыта** | TSM public statistics; локальный Ledger/капитал; исследованные item/realm/crafter кэши; проектирование каталога. | Нет подтверждённой глубины рынка/auction IDs; нет действующего UE history; нет полного глобального импорта рецептов и runtime CraftSim export. |
| **Без Blizzard; UE когда-либо разрешён отдельной SourcePolicy** | Дополнительные способности из матрицы согласно реально разрешённым endpoints/тарифу и после live-валидации. | Не появляется автоматически item metadata, гарантия исполнения, право бессрочного архива, платная детализация или глобальная полнота. |
| **Без Blizzard; будущий этап 3** | Полный обход согласованных доступных альтернативных корпусов, проверяемый экспорт CraftSim, версия каталога с coverage report. | Не допускается обещание полного знания всех механик из наличия ATT tree или кэша одного аккаунта. |

**NB-D1 — исключить зависимость от числового Blizzard ID там, где источник работает по slug. DOC + реализовано/SYN; UE REAL отсутствует.** Регион и выбранный realm slug задают область исходного набора. В текущем коде список группы получает `provider_connected_realm` и hash(provider, game, region, sorted unique slugs), без numeric ID. Проверены перестановки, конфликты, отсутствие/истечение evidence и запрет переноса mapping в TSM; см. [тесты](../../tests/test_market_groups.py). Локальный 1604 остаётся library assertion, не результат запрещённого API запроса. Это позволяет работать с TSM сейчас и избегает ложного слияния миров.

**NB-D2 — явные capabilities вместо имитации полноты. PLAN.** Base statistics допускаются для исследовательских оценок; они не дают объём покупки по минимальной цене, вероятность продажи или гарантированную доступность варианта. Для отсутствующих depth/variant/executed-sales полей сохраняется unknown/unavailable. Ни один read-only рынок, включая прежний Blizzard API, не гарантирует фактическую покупку или продажу.

**NB-D3 — сохранить глобальную задачу каталога. PLAN.** Удаление Blizzard источника не удаляет старые дополнения, непрофессии и неизвестные семейства из требований. Число 71 в CraftSim не является знаменателем глобального каталога. Для прежнего profession/tier/recipe маршрута нужен явно версионированный replacement manifest ATT и разрешённых дополнительных источников, а не незаметное сокращение до локальных профессий.

**NB-D4 — раздельные часы и воспроизводимость. PLAN.** Source scan, generated, received и фактический available_at остаются отдельными. Fingerprint повторного содержимого не создаёт новое наблюдение рынка. Простой worker создаёт gap; историческая дата ряда не backdate-ит локальную доступность. После удаления raw/normalized по политике сохраняются идентичность и явный `replay_unavailable_due_to_retention`, а не обещание восстановления цен из хеша.

**NB-D5 — отсутствие прямого подключения не скрывает upstream. PLAN.** TSM/UE могут использовать исходные Blizzard auction snapshots; два провайдера поэтому не обязательно два независимых свидетельства ликвидности. Проект не запрашивает Blizzard credentials и не запускает Blizzard runtime, но lineage полученных от разрешённого поставщика данных всё равно сохраняется.

## 7. План проверки альтернативного глобального каталога — только этап 3

Базовые требования полноты из [T3-02/R2](transformation-discovery-r2.md#6-усиленный-t3-02-полный-обход-выбранных-корпусов) сохраняются. Из manifest должна быть явно удалена рабочая зависимость от Blizzard profession/tier/recipe API; его прежняя область заменяется перечислимым ATT корпусом и разрешёнными дополнениями. Это изменение источника, не уменьшение цели.

1. Зафиксировать ATT commit/tree, shared/config dependency closure, Retail/version filters, лицензию каждого слоя и ожидаемые roots. Baseline R2: 1874 Lua blobs вне `.config/`, 2722 tree entries, `truncated=false`. Это число файлов выбранного дерева, не число действующих рецептов или доказательство полноты игры.
2. До импорта задать раздельные denominator по профессиям, tier/expansion и непрофессиональным семействам. Связи с recipeID/spellID/itemID разрешать явно; ATT taxonomy не считать автоматически Blizzard ID taxonomy.
3. Дать каждому объекту terminal disposition: semantic candidate, validated, historical/out-of-scope, duplicate или quarantine с причиной. Неизвестная грамматика/недоступный branch остаётся незавершённым обходом, а не успешной пустотой.
4. Вводить eligibility/economic fields только с evidence: расход, выход, quality, binding/tradeability, требования, cooldown/limits и provenance. Список коллекционных результатов не нормировать в равномерную вероятность; не подменять среднее PMF или joint distribution.
5. Подтверждать варианты и личные характеристики предусмотренным отдельным экспортёром CraftSim только после разрешения этапа 3. Это не ограничивает глобальный discovery профессиями аккаунта и не снимает известные C11/C21 проблемы модели.
6. Выпускать coverage report для всех Retail expansions и семейств, включая непокрытые. При отсутствии обязательного полного источника — `PARTIAL / BLOCKED SOURCE`; широкий PASS не выводится из smoke-test или нескольких успешных рецептов. Изменение области приёмки требует отдельного явного решения пользователя/аудитора.
