## Результат

Реализованы рыночные адаптеры TSM/UE, проверка данных, отдельная SQLite,
атомарные снимки, видимость после commit, last-good, ограниченное хранение,
очередь с lease, provider quota/cooldown, restart/gap, GET transport с
ограничениями размера/времени/распаковки и CLI. Пять настоящих CSV TSM
импортированы без ключей; повторная проверка дала пять HTTP304 с сохранением
первоначальных snapshot IDs/hash/времён. Blizzard HTTP/OAuth отсутствует в
рабочем маршруте и отклоняется транспортом до сетевого вызова.

Отдельно разобраны история, локальные активы, CraftSim и общий каталог.

## Обоснования и сохранение предыдущей работы

| Изменение | Основание и предел |
|---|---|
| TSM bootstrap без любых ключей | Фактически доступный публичный источник цен; не предоставляет количества и уровни предложения |
| Полный запрет Blizzard в runtime | Прямое требование пользователя; нет optional fallback, секреты не загружаются, legacy jobs возвращают disabled. Offline adapter сохранён без сетевого подключения |
| UE-группа вместо numeric connected ID | Документированный membership источника достаточен для собственной идентичности; effective time и cross-provider mapping неизвестны. Conflicts не сливаются |
| UE адаптер подготовлен, сеть выключена | API требует собственного UE ключа; общий ToS и описание API требуют отдельного согласования применимости к систематическому хранению. Это текущая политика проекта, не правовое заключение |
| Отдельная рыночная БД | Принятые активы/Ledger не переписываются; миграция market 1→2 добавляет durable provider cooldown без потери снимков |
| Ограниченный TSM кэш | Публичное потребление подтверждено; бессрочный архив/републикация явно не разрешены. Четыре часа — наша операционная политика, не условие лицензии |
| Будущий ATT traversal и локальные кэши | Сохраняют глобальную задачу discovery без Blizzard indexes; полнота доступного корпуса не полнота игры. CraftSim не становится всемирным каталогом по 71 локальной записи |

Принятый пакет этапа 1 сохранён до изменений в `research/baselines/stage-1-r2.zip`
(62 файла + manifest), SHA-256
`94a1e497a7121273c71454b09aeb682b6feb26baa2308fa008afe324bb6dd94e`.
Исходный manifest внутри проверен 62/62. Отчёты `docs/reviews/`, старые результаты

## Доказательства

Команды повторения — [runbook](stage2-runbook.md). **309/309 тестов PASS за 13,153 с**,
включая прежние 160 тестов этапа 1. Финальная автоматическая
сводка тестов и хешей — [stage2-checks.json](stage2-checks.json).
Тесты SYN/MOCK проверяют данные, сбои, размеры, сроки, секреты и запрет Blizzard;
они не выдаются за проверку настоящего UE-ответа.

REAL: [stage2-live-evidence.json](stage2-live-evidence.json), [повторный импорт окончательной версии](stage2-final-import-evidence.json), дополнительные
измерения нормализатора — [stage2-tsm-validation.json](stage2-tsm-validation.json).

Всего raw 4 467 043 байта, нормализованные UTF-8 JSON 30 717 668 байт;
измеренный файл БД на первом комплекте 53 948 416 байт (включает страницы/накладные расходы).
Повторная проверка пяти файлов заняла 4,01 с; все 304, заголовок Authorization
не отправлялся, Blizzard requests=0, SQLite quick_check=ok. Инструментированный
разбор самого большого CSV ранее занял 1,819 с, peak tracemalloc 57 034 884 байта.
Это замер агрегатов одного региона/мира, не размер полного рынка UE.
Экстраполяция при шести меняющихся наборах в сутки: raw около 26,8 MB/день,
нормализованное содержимое около 184,3 MB/день без страниц/индексов. Это сценарий
нагрузки, не разрешение архива и не наблюдённая частота обновления; при текущем
4h retention долгий архив не формируется. File high-water mark SQLite может
сохраняться после очистки, но secure_delete удаляет содержимое освобождённых страниц.

Внутренняя независимая проверка выявила и закрыла три проблемы: 429 ограничивал
только один job вместо всего источника; диагностика не показывала capabilities;
неизменный raw hash скрывал обновление нормализатора. Добавлены регрессии и
`normalizer_revision`: при изменении кода запрос получает полный пакет,
сохраняет новую нормализованную ревизию, старую не переписывает. Финальный
REAL-прогон занял 7,41 с, пять HTTP200 без Authorization; raw hashes и source
scan times прежние, записи 6–10 — **ревизии парсера, не новые наблюдения рынка**.
После этого в БД 10 ревизий, 89 182 208 байт, quick_check=ok. Исходные числа
из первого прогона оставлены с собственным свидетельством. Подготовительные
CSV-копии исследования удалены после сверки с БД; для них сохранены только
диагностические manifest/hash, см. [свидетельство очистки](stage2-research-cleanup.json).

Недоступные исходные auction ID, bid/time_left, бесплатные полные варианты,
полный текущий справочник и гарантии покрытия перечислены по наборам в матрице.
Их отсутствие не компенсируется предположениями. Цена/исчезновение объявления
не доказывают продажу или исполнение ни с Blizzard API, ни без него.
Длительный разрешённый исторический архив и облачная передача рыночных данных
остаются отдельным вопросом прав; воспроизводимость после удаления ограничена.

Состав передаваемого пакета фиксирует [stage2-package-manifest.sha256](stage2-package-manifest.sha256).

код и документация, внешний недостаток данных отделён от внутренних проверок.
Следующий этап требует отдельного решения пользователя.
