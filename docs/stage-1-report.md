## 1. Полученный результат и границы

Работают read-only импорт четырёх установленных аддонов, безопасный ограниченный
Lua-data parser, независимые адаптеры, согласование денег/имущества, нормализация
TSM Ledger, SQLite с миграциями, карантин, атомарное восстановление и локальный
CLI. CraftSim распознаётся как сохранённая структура/кэш, без вызова его движка.
Пользовательские суммы доступны локально; стандартная диагностика обезличена.

Нет рыночных клиентов, сервера/веб-интерфейса, аддона-моста, поиска цепочек,
виртуальной торговли или ИИ. Чтение addon TOC подтверждает установленную версию,
не runtime. Реальная прибыль/NAV не вычисляются без необходимых фактов.

## 2. Обоснования решений и устройство

| Решение | Основание и проверяемый предел |
|---|---|
| Python stdlib, изолированное `.venv`, CLI | Этап 1 требует проверяемого локального импорта; FastAPI/UI отложены до своих этапов. Внешних зависимостей нет; OOP Store и dataclass Source/StableFile/ParseLimits отделяют контракты. Системный Python не изменён |
| Литералы Lua вместо interpreter | Файлы данных не получают права исполнить код. Strict UTF-8/byte escapes, size/depth/node/string/time bounds; unsupported синтаксис отклоняется |
| Наблюдения и текущая проекция отдельно | mtime не время каждого поля; исходные bytes/hash и нормализация сохраняются. Неизменный текущий hash не новая сделка, но A→B→A может быть новым наблюдением. Старые bytes не стираются |
| Выбор источника поля и canonical owner | GX/BagSync не складываются. GUID/unique alias, явное межлицензионное владение, singleton warband, конфликты и неизвестные контейнеры вместо выдуманного точного капитала |
| Ledger как версии мультимножества | В TSM нет transaction UUID. Сохраняются одинаковые строки, подтверждённый прирост агрегата, tombstones и ambiguity; пропущенное семейство не пустая история |
| DELETE journal вместо WAL | Локальная SQLite 3.50.4 не объявлена исправленной. Выбран разрешённый [T1-10](acceptance-tests.md) безопасный режим, FULL sync, сериализованная запись, запрет WAL. Аварии/миграции/backup реально проверены; переход к WAL требует отдельного выбора runtime |
| Доступность после commit | NULL pending→посткоммитная отметка; crash recovery публикует позднее без повторного Ledger delta. Момент события/mtime/получения/доступности разделены |
| Ручная связь отдельным overlay | Связь привязана к проверенным ревизиям; импорт перепроверяет её количество/контекст/неопределённость. Requires_review исключён из подтверждённых allocations; история и отзыв сохраняются |

## 5. Найденные и исправленные технические дефекты

**Ответ на S0-06 low из принятого аудита R2:** в
[temporal-evaluation-r2.md](research/temporal-evaluation-r2.md) удалена
подготовительная инструкция о будущей нумерации. Зафиксированы T5-02 — modes,
T5-08 — actual/public/daily, T5-09 — LLM knowledge/claim gate, T5-10 — stored
replay, T5-11 — context isolation; T6-09 только blind factor discovery.
Добавлена карта T2-A* без изменения смысла сценариев. Правка входит в текущий
stage1 manifest; принятые исходные bytes R2 остаются в архиве.

Работа делилась между независимыми субагентами parser/reader, assets и Ledger;
root интегрировал хранение/CLI. Внутренняя взаимная вычитка не заменяет внешнего
аудитора. Все следующие находки подтверждены кодом или синтетическим repro и
имеют регрессионные проверки:

1. Windows `lstat`/`fstat` дают разные значения ctime неизменного файла —
   сравнение заменено на inode/device/size/mtime и два полного содержимых.
2. A→B→A ошибочно оставлял текущую проекцию B — версия raw отделена от нового
   наблюдения; повтор только текущего hash идемпотентен.
3. Отсутствующее семейство Ledger ошибочно восстанавливало tombstones —
   reconciliation только реально присутствующих семейств, остальное неизменно.
4. Преждевременный available_at — durable commit перед публикацией времени,
   отдельное восстановление pending без повторных финансовых эффектов.
5. Cache CraftSim мог вывести crafter_key в обычном status — default только
   counts/status; частные строки доступны лишь `--details`.
6. Ledger не учитывал почтовое происхождение времени expired/cancelled/
   crafting-order — метки исправлены по установленному Mail.lua.
7. COD/Auction-buy split invoice и Vendor batch не давали заявленной точной
   границы округления — границы теперь unknown; Auction-sale net/unit отдельно.
8. Изменение uncertainty уже пропавшей строки не создавало revision — добавлена
   версия и журнал изменения статуса.
9. Две лицензии могли дублировать общие предметные копии — canonical container,
   multiset comparison, альтернативы и конфликт вместо двойного inventory.
10. Первоначальная защита region/ownership ввела versioned policy и
    requires_reimport, но аудит нашёл неполноту на непустом Ledger. Исправление
    S1-01 отделяет identity transition от missing families и добавляет
    конфликт/явное восстановление с backup; подробности в ответе R1.
11. Лимит конфигурации проверялся после полного чтения — чтение ограничено
    1 MiB + 1 байтом; oversized input отклоняется до полной загрузки.
12. Некорректная версия repository CraftSim могла дойти до сериализации —
    int/null schema validation отклоняет нечисловой объект заранее.
13. Параллельный publisher мог взять timestamp до ожидания блокировки writer —
    теперь время берётся после `BEGIN IMMEDIATE`; проверено двумя процессами
    с задержанным commit и аварией writer до публикации.

S1-01: переход контекста без второго Ledger/финансового приращения, явный
requires_resolution и восстановление из raw с backup/новым периодом учёта.
S1-02: ограниченная конвертация строковых чисел BagSync до int, безопасный
карантин и продолжение scan/watch. S1-03: действительность ручных связей по
ревизиям/контексту, append-only история проверок/редакций/отзывов.

Новая схема 3 добавляет служебные таблицы; миграции 1–2 и исходные записи
сохранены. Подробный ответ, обоснования и тесты по каждому ID находятся в

реальных bytes проверил empty→buy/repair→repeat→backup/restore с нулём новых
дублей. Рабочая пользовательская БД не мигрировалась/не перестраивалась;
проверена неизменность исходных приватных материалов. Результаты и дата нового
запуска: [доказательства исправлений](stage1-r1-fix-evidence.json).

## 6. Неподтверждённое, ограничения и противоречия

- **Q04 — непустая история получена.** Реальная покупка и ремонт импортированы,
  расход согласован с GX/BagSync; прежний блокер отсутствия любых операций снят.
  Продаж, доходов, возвратов, отмен и других типов операций в новом слепке нет.
  Для них реальная интеграция не объявляется PASS; специальные сделки для
  расширения проверки не требуются.
- **Q05 — действия уточнены.** Пользователь уже открыл сумки/банки основных
  персонажей. Данные аддонов прочитаны и автоматически согласованы; повторять
  этот обход или переписывать суммы не требуется. В выполненном пользователем
  reload-опыте наблюдалась запись изменённых файлов и точное совпадение расхода
  с уменьшением кошелька. Дополнительные сценарии
  переносов, доступного нулевого банка и независимой игровой сверки остаются
  непроведёнными экспериментами, а не утверждением, что пользователь не
  синхронизировал аддоны. CraftSim runtime относится к этапу 3.
- **SQLite.** Исправленная сборка не устанавливалась; безопасный DELETE-режим
  предусмотрен архитектурой и T1-10. Попытки повторно получить web-документацию
  завершились ошибкой соединения. Источник E-TECH-01 остаётся ранее проверенным,
  не новой успешной сетевой пробой. Фреймворк/UI на этапе 1 не добавлялись.
- **Полнота имущества/себестоимость.** Source table/schema не доказывают полный
  осмотр или возможность продажи. Точный NAV, полная прибыль и неизвестные
  выходы/затраты не подменены нулями; численные параметры риска не вводились.
- **Несколько лицензий.** Общая собственность требует явной настройки после
  подтверждения пользователя. По имени папки/персонажа она не угадывается.
- **Парсер.** Поддерживается подмножество Lua 5.1 данных, не любой Lua и не binary
  strings; неподдержанные форматы quarantine. Лимиты — защита процесса.
- **Хранение.** База/backup приватные и gitignored, но не зашифрованы; права
  наследуются от локального Windows-каталога. Долгая ретенция/объёмные истории
  и производительность на полном непустом Ledger ещё не измерены. Автоматическое
  удаление не введено. CLI watcher не служба/автозапуск.
- **Scope.** Широкое упоминание CraftSim в этапе 1 трактуется согласно принятому
  плану как чтение структуры; мост и runtime calculator относятся к этапу 3.
  Цена/рынок и full PnL зависят от следующих этапов и не реализованы скрыто.
