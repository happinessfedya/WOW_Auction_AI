# Дополнительное исследование R2: перечисление непрофессиональных преобразований

Дата: 26.10.2026. Ответ разработчика на **S0-01** из [независимого аудита R1](../reviews/stage-0-review.md). Область — исследование и проектирование этапа 0. Полный импорт, исполнение Lua/сборщиков, запуск WoW и игровые операции не выполнялись. Прочитаны публичные исходники и несколько настоящих файлов данных; это не проверка механик в игре. Старые результаты C01–C22 в [craft-transformations.md](craft-transformations.md) сохраняют собственные даты и пределы.

**Решение:** первоначальное discovery должно обходить весь заранее зафиксированный корпус выбранных источников с проверкой завершения. Небольшие ручные примеры служат проверкой маршрута, а не первоначальной базой. Для контейнеров, NPC, особых систем и периодических действий найден конкретный широкий корпус AllTheThings (ATT); для item-use получены настоящие таблицы связей ItemXItemEffect/ItemEffect. Эти источники перечисляют кандидатов, но не дают полной экономической модели каждой операции. Схемы WoWDBDefs по-прежнему не считаются данными.

## 3. Семейство → перечисление → поля → предел → резерв

Общий корпус A: **все** Lua blobs standard вне .config, обнаруженные D2-02, плюс необходимые pinned shared/constants/functions и конфигурации D2-03. Файлы .dynamic, NYI, Classic и региональные ветки не исчезают из manifest: для каждого фиксируется решение по Retail preprocessor/build/scope. Список известных примеров не используется как allowlist. Полный глобальный знаменатель игры неизвестен.

Корпус B: все строки полученных ItemXItemEffect и ItemEffect выбранного build; дополнительные **полные, разрешённые** Item/ItemSparse/SpellEffect/SpellReagents/ItemExtendedCost, когда найден и проверен источник фактических данных. Их отсутствие сейчас отражено отдельно; WoWDBDefs только описывает структуры.

## 5. Права, версии, ограничения и неподтверждённые предположения

1. **Права:** pinned ATT LICENSE позволяет использование именно лицензируемого автором software с сохранением notice; независимая правовая оценка dataset/upstream не проведена. CurseForge ARR не игнорируется и не переносится автоматически на другую ревизию. Wago/Blizzard/Wowhead происхождение не становится разрешением на массовый reuse, cloud forwarding или redistribution. Перед массовым копированием фиксировать artifact-specific условия и допустимые local/cache/distribute/cloud modes. Не публиковать harvested arrays по общей MIT-надписи. Здесь приведены короткие адресные факты, массивы не перенесены.
2. **Wago и hotfix:** D2-06 подтверждает URL, которым пользуется автор ATT, но не SLA/API-права проекта. useHotfixes означает, что один build сам по себе недостаточен для побайтовой воспроизводимости; хранить фактический response hash/retrieved_at и snapshot provenance. Ветка/mtime/commit time не равны моменту вступления каждой механики в силу.
3. **Неполная SpellEffect:** даже при устранении Transport closed зеркало не покрывает произвольные create-item effects; это не технический сбой, который можно скрыть retry. Полный разрешённый dataset не получен. Output lookup design остаётся H до фактического теста.
4. **Язык ATT:** статический extractor ещё не создан. Он должен понимать literals, documented constructors, constants, наследование, условные compilation tags и разрешённый subset sym; остальные узлы получают explicit unresolved. Lua/compiled harvesters/build scripts для импорта не запускать. Parser source пригоден для исследования semantics, а не повод исполнять сторонний код.
5. **Полнота контейнеров/разрушения:** нет универсального подтверждённого bulk loot/PMF source. Список коллекционных наград не даёт probability mass, zero outcomes, gold, co-products или размер расхода. Нельзя нормировать список в uniform probability, считать отсутствие записи нулевой вероятностью или выдавать среднее за joint distribution.
6. **Персонажи:** хранить требования механики, но не фильтровать глобальный initial catalogue по профессиям/персонажам пользователя. Runtime eligibility fallback для имеющихся предметов не становится проверкой общего допуска всех действий на его персонаже.
7. **Граница принятия:** этап 0 закрывает недостаток конкретного проектирования маршрута, а не утверждает полную готовность всех внешних источников. Решение о закрытии S0-01 принадлежит независимому проверяющему.

## 6. Усиленный T3-02: полный обход выбранных корпусов

Это **будущий** критерий этапа 3. На этапе 0 он не запускался.

**Manifest до импорта:** source IDs, pinned revision/build/hash, права и режим использования, точные roots/filters, ожидаемый file/page/table universe, inclusion/exclusion rules, dependency closure, retry limits и доказуемое условие конца. Базовый согласованный маршрут — A целиком, B из двух реально найденных таблиц плюс доступные разрешённые полные расширения, Retail-секции C14 и Blizzard profession/tier/recipe indexes. Источник с неподтверждёнными правами/данными не превращается в молча пустую коллекцию; его blocked scope объявляется отдельно. Если к этапу 3 источник заменён, manifest и rationale обновляются до проверки; удалять неудобные семейства или дополнять allowlist только примерами ради PASS нельзя.

Для **PASS обхода** одновременно требуется:

1. У источника получен полный индекс: для tree проверены truncated=false или выполнен рекурсивный обход отдельных subtrees; для paginated API исчерпаны страницы. Для A baseline1874 — контрольный счётчик этой ревизии, не число подтверждённых transformations. File bytes/hashes проверены; зависимые shared/config refs имеют terminal disposition.
2. **Все** включённые файлы/страницы/строки обработаны; нет pending/retry/fetch-error/неучтённых записей. Заранее обоснованные out-of-scope/rights exclusions остаются в знаменателе и отчёте, а не маскируются «успешной обработкой». Неизвестная grammar/error целого файла — незавершённый обработчик, не основание пропустить файл и выдать full PASS.
3. Все обнаруженные candidate nodes получили один terminal disposition: semantic record; duplicate со ссылкой; explicit out-of-scope/historical; quarantine с конкретным недостающим evidence. Нет отрицательного фильтра «интересующие нас пять IDs». Unknown-family и unresolved references учтены отдельно; известные поддерживаемые конструкции нельзя массово карантинить ради формального завершения.
4. Сверены равенства fetched/processed/excluded/error по manifest и extracted/normalized/duplicate/rejected/quarantined по candidate IDs. File total и operation total не смешиваются. Все 12 era×family buckets существуют, включая нулевые и unknown; отсутствие класса не означает отсутствия механики в игре.
5. Обработчик идемпотентно возобновляется после ошибки в середине списка; повтор не создаёт двойные входы/выходы, а смена source hash создаёт новую версию.
6. Экономически неполный candidate импортируется как candidate/quarantine, не reliable recommendation. Неподтверждённые PMF, расход, bind, output или reset не заменяются дефолтом. Отдельно показываются source traversal complete и semantic/current coverage: первое не доказывает второе.
7. Source gaps D2-15/D2-16 и права D2-04/D2-06 имеют именованный статус. Если обязательный выбранный корпус недоступен и замена не подтверждена, результат **PARTIAL / BLOCKED SOURCE**, а не полный PASS T3-02. Более узкая приёмка требует явного изменения scope пользователем и аудитором; разработчик не решает это скрыто.

**Обязательные отрицательные сценарии:** остановка после первого batch; пропуск старой era; truncated tree; пропущенная страница; нераспознанный sharedData/sym; removed season P7; Classic-only Season of Discovery; условная цена в комментарии P5; _cost P4; ошибочное приравнивание daily flag к daily loot cap P5; отсутствующая item-effect row P9; ошибочная подстановка ATT-filtered SpellEffect как полного набора. В каждом случае либо соответствующая запись имеет доказуемый disposition, либо заявленный full traversal/semantic validation не проходит.

Требование «максимально много подтверждённых преобразований при первом запуске» остаётся: все доступные согласованные корпуса обходятся полностью, затем все достаточно подтверждённые операции импортируются. Маленькая выборка не заменяет ни discovery, ни отчёт по реальным пробелам.

## 7. Воспроизведение исследовательских проб

Все адреса immutable; повторять только чтение, не запускать .bat/.exe/Lua из источника.

1. Получить Git tree из D2-02. Посчитать элементы type=blob, path оканчивается .lua, path не начинается .config/. Проверить 1874, общее число2722 и truncated=false. Это точная воспроизводимая процедура, не семантический парсер.
2. Для файла standard использовать GitHub Contents API: base `https://api.github.com/repos/ATTWoWAddon/AllTheThings/contents/.contrib/.db/standard/`, URL-encoded path из D2-07…D2-13 и query `ref=3d0461d9740940e09c9cb19390467ed6ec39cb9c`. Сверить blob SHA из таблицы или Git tree. Точно так же доступны две CSV D2-05.
3. Прочитать CSV корректным CSV reader. У ItemXItemEffect ожидаются ID/ItemEffectID/ItemID; у ItemEffect — ID/LegacySlotIndex/TriggerType/Charges/CoolDownMSec/CategoryCoolDownMSec/SpellCategoryID/SpellID/ChrSpecializationID/PlayerConditionID. Посчитать строки без header и сопоставить указанные item IDs через ItemEffectID→ID. Заголовки/счётчики и результаты P8/P9 — реальный результат этого исследования.
4. Проверить .tools directory, SpellEffect.regex и CSVCleaner Program.cs: подтвердить фильтрацию и отсутствие двух item-effect regex. Это необходимый тест качества источника; успешный HTTP200 недостаточен.
5. Для P1–P7 сверить указанные строки, родительские условия и активный код отдельно от комментариев. Никаких выводов о runtime по результату этого текстового теста.
6. При сетевой недоступности зафиксировать точную ошибку и источник. Сохранённый pin/blob ID позволяет независимую повторную проверку; в проект не сохранена копия внешних data arrays.

Проверенные сейчас результаты: enumeration metadata, два CSV counts и их адресные joins, восемь небольших тематических ATT Lua-файлов, конфигурации/лицензия/загрузчик/cleaner и generated API. Непроверенное: полный семантический traversal, реальные WoW операции, актуальная вероятность/продажа, полные yields и внешние права массового распространения.
