## S2-01: возраст источника и регрессия времени

Исправлено в `market_freshness.py` и `market_storage.py`. Успешная загрузка,
наличие сохранённого содержимого (`cache_available`) и пригодность текущего
рынка (`usable`) теперь независимы. Полный HTTP200 может быть успешно разобран,
но старый/неизвестный/future источник не получает положительную пригодность.
`market-status` показывает отдельное `source_freshness` с возрастом, порогом,
семантикой и версией политики. Ошибка последнего refresh также не скрывается.

| Источник/набор | Рабочая граница возраста | Основание и предел |
|---|---:|---|
| TSM commodity, realm items/pets | 8 часов по source scan | Две локальные 4-часовые возможности обновить кэш; документация говорит о нескольких часах, но не гарантирует точную cadence |
| TSM region items/pets | 48 часов по source scan | Суточный выпуск и один дополнительный день допуска; просрочка не маскируется новым received_at |
| UE current со snapshot/положительным lastSeen | 6 часов | Проектный предел для источника с примерно часовыми upstream наблюдениями; это не SLA и не REAL измерение |
| UE regional aggregate без upstream clocks | Не подтверждён | Свежая генерация файла не удостоверяет возраст всех его рынков |
| UE history/reference/quantity0 | Не current-price input | Старые history points и lastSeen при нулевом количестве сами по себе не ошибка; время генерации/ordering хранится отдельно |

Все численные границы — **версионированная операционная политика проекта**,
а не условия лицензии и не измеренная частота поставщика. Документированные
часы/частоты: [TSM](https://tradeskillmaster.com/public-data),
[UE](https://undermine.exchange/api.html).

Для одинаковых provider/dataset/scope откат известного clock сохраняется как
отдельное свидетельство с `source_regression_kept_last_good`, не меняя current
и его validators. Утрата известных часов или несопоставимая группа дают явный
статус. Корректировка с тем же временем и другим содержимым допускается как
новая ревизия. Clock descriptor не содержит цен и сохраняется после retention:
старый файл нельзя заново объявить новым рынком после удаления raw.

Дополнительная независимая проверка исправления обнаружила крайний случай
UE positive→zero→older positive. Нулевое количество больше не стирает известное
время положительного снимка; наследование watermark ссылается на прежний
snapshot. LastSeen используется для порядка, а не для признания нулевого
количества текущей котировкой. Будущий clock при получении остаётся помеченным
до нового полного наблюдения: течение местного времени не снимает аномалию.
Изменение `market_freshness.py` входит в fingerprint нормализатора и требует
повторной проекции, сохраняя исходную доступность старой записи.

Регрессии: `test_market_freshness.py`, `test_market_freshness_integration.py`:
A→B→A, equal-time correction, stale200/304 и пересечение порога, unknown/future,
restart/expiry/reacquisition, replay, parser revision, UE history/zero/mixed groups.

## S2-02: точная привязка HTTP validators

Schema **3** добавляет `http_validators` с job/snapshot/normalizer revision,
ETag, Last-Modified и поколением; запись меняется **в одной транзакции** с
current. Старые jobs.etag/last_modified очищаются и больше не используются.
Миграция доверяет заголовкам соответствующего snapshot, не потенциально
несогласованным полям jobs. Raw/normalized/received/available прежних снимков
не переписываются; новый clock descriptor — добавленные метаданные.

На каждом полном 200 отсутствующий validator соответствующего вида очищается,
включая повтор тех же байтов. Ошибочный/частичный/регрессирующий ответ не меняет
validators last-good. 304 подтверждается только при совпадении **фактически
отправленного** conditional context с retained snapshot, его поколением,
нормализатором и действительным lease. Неподтверждённый или противоречивый 304
даёт безопасную ошибку, сбрасывает validators только своего задания и планирует
ограниченный full fetch; немедленного цикла запросов нет. При потере lease
чужие validators/health не затрагиваются, следующие задания продолжаются.

Это соответствует смыслу выбранного representation в
[RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-none-match).
Регрессии `test_market_validators.py`: отсутствие одного/обоих validators,
каждый тип отдельно, same-body200, unsolicited/conflicting304, parser change,
ошибка схемы/partial, crash до/после commit, migration2→3, takeover и cleanup race.

## S2-03: общий deadline, завершение и очередь

Операционный socket timeout не ограничивал DNS/headers/весь download. Default
HTTP теперь выполняет один запрос в отдельном короткоживущем spawn-процессе,
а родитель контролирует единый monotonic budget (по умолчанию 30 с, максимум
60 с), включая запуск, сеть и получение результата. По истечении срока процесс
завершается; на terminate/kill/join выделено максимум ещё 1 с. Бессрочного
сетевого потока после timeout нет. Большой ответ передаётся через ограниченную
shared memory с handshake и очисткой, без блокирующего recv большого payload
или временных raw-файлов. Внутри дополнительно используются `read1`, remaining
socket timeout и проверки после распаковки/обработки.

Основание выбора: [urllib timeout](https://docs.python.org/3.13/library/urllib.request.html#urllib.request.urlopen)
относится к блокирующим операциям; [процессы](https://docs.python.org/3.13/library/multiprocessing.html)
позволяют прервать зависшую операцию целиком. Injection opener оставлен как
синхронный тестовый шов; production использует отдельный процесс.

Lease остаётся 180 с, не увеличен для маскировки проблемы. При истечении или
перехвате lease commit/304 запрещены; потеря владения при cleanup/finish не
останавливает независимые jobs. Deadline сохраняет last-good и назначает
ограниченный retry. Тесты не выдают сдвиг искусственных часов за реальный сон ПК.

Регрессии: `test_market_deadline.py` (slow drip, gzip, no-length, headers,
общий бюджет, большой IPC, принудительное завершение реально запущенных
синтетических процессов и удаление shared memory) и queue/lease cases в
`test_market_validators.py`. Исходные HTTP size/framing/redirect/secret tests сохранены.

## S2-04: изоляция отключённого UE

Конструктор worker и status/resolve не загружают секреты. `_provider_secrets`
вызывается только перед запросом включённого UE после source-policy/paid gate.
Ошибка нужного ключа локальна UE job; следующий TSM job выполняется. Секрет
проверяется заново при следующей попытке, поэтому исправление настройки не
требует пересоздания worker. При допустимом env-ключе fallback-файл не читается.
Неиспользуемые Blizzard fields не проверяются и не загружаются.

Диагностика до чтения сообщает `not_inspected, configured=null`, а не выдуманное
отсутствие ключа. `test_market_lazy_secrets.py` проверяет malformed/missing/
unreadable файл/env при disabled/policy-blocked UE, допустимый UE с ошибкой,
восстановление, injected secrets и отсутствие loader calls у CLI.
