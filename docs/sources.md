## Предпочтения и условия переключения

Прежняя предложенная связка с прямым Blizzard источником **отменена пользовательским решением**. TSM Public CSV обеспечивает рабочий путь без регистрации и ключей; локальный AppData остаётся отдельным агрегированным источником. UE подключается отдельно после допустимого доступа/условий и реальных проверок; сейчас его сеть заблокирована до разрешения противоречия условий из раздела 5 [матрицы](research/stage-2-no-blizzard-alternatives.md). Наличие ключа само по себе это ограничение не снимает. Документация или mocks не делают UE работающим источником глубины. Снижение capabilities видно потребителю: TSM не заменяет стакан/количество/точный вариант. Прямой Blizzard источник и обход закрытого UE через внутренние файлы сайта не используются.

Рыночная identity не требует выдуманного numeric ID: регион+provider slug идентифицируют запрошенный scope; подтверждённый UE список `request.realms` может образовать версионированный ключ группы поставщика с hash/временем получения/составом. Проверяются присутствие запрошенного slug и конфликты membership. Это свидетельство UE, не независимое подтверждение Blizzard и не автоматическое разрешение слить TSM-группу. Общий upstream поставщиков сохраняется в lineage; два домена не означают две независимые рыночные выборки.

Для имущества приоритет устанавливается по области и свежести, не глобально по аддону: GX cash+lastSeen, BagSync inventory, TSM Ledger events. Согласование показывает расхождения, time unknown и неполноту. TSM net sales не позволяют заново вычитать процент комиссии; старые TSM остатки не превосходят новые денежные наблюдения GX.

Данные преобразований собираются объединением источников. На первом запуске будущего этапа 3 обходятся все разрешённые каталоги всех Retail дополнений. Подтверждённое загружается, пробелы/unknown probability/unsupported отмечаются по каждой ячейке [матрицы](research/craft-transformations.md). Права и договоры относятся отдельно к коду, схеме, содержимому, хранению, облачной передаче и распространению.

В R2 для непрофессиональных семейств предложен закреплённый корпус AllTheThings с полным Git-tree обходом стандартной Retail-ветви, адресными старыми и современными пробами и отдельными DB2-связями. Текущее решение расширяет этот маршрут на профессиональный discovery вместо обязательных Blizzard indexes; пригодность разрешённых build-данных подтверждается отдельно. Это каталог обнаружения кандидатов, не подтверждённая база выходов/вероятностей. Цепочки include/macros/version filters и неэкономические коллекционные записи получают явный disposition. Лицензия конкретного commit и права upstream данных проверяются раздельно; фильтрованная таблица зеркала не выдаётся за полный DB2. Исходные paths, commit, counts и блокеры — [исследование D2](research/transformation-discovery-r2.md), актуальная замена источников — [матрица](research/stage-2-no-blizzard-alternatives.md). T3-01/T3-02 требуют полного согласованного traversal, а не наличия sample batch; реализация только после разрешения этапа 3.

## Нагрузочная и временная политика

UE квоты и endpoints приведены в [M01](research/market-sources.md); M08/M09 — историческое исследование исключённого Blizzard пути. Не использовать старый TSM API с придуманными credentials, не скрейпить внутренние файлы Undermine вместо опубликованного API. Начинать с выбранного пользователем региона/мира; обход всех миров не нужен для старта. Отслеживать источник snapshot time, publication time и ingest time раздельно. История TSM scalar `historical` не заменяет свечи/лоты; daily Undermine — не обязательно цена закрытия.

У Undermine final daily выбирается снимок по максимальному количеству за весь день [T2-S02]. Его нельзя использовать до конца соответствующего source period, даже если победивший снимок был утренним. В прочитанном контракте не подтверждены timezone/finalization/историческая публикация каждой ревизии; сегодняшний lastUpdated файла их не заменяет [T2-S03]. Поэтому хранится PublicationAvailabilityClaim точного содержимого; неизвестные bounds исключают строку из основной публичной реконструкции, допущения только в отдельно названном сценарии. Фактический available_at при этом не меняется. Эти ограничения относятся также к derived features и поздним исправлениям других поставщиков, если их revision history неизвестна.

Новая версия источника или schema drift вызывает quarantine и контрактные тесты. Fallback меняет capabilities: если глубина исчезла, количественно исполнимая рекомендация не продолжается с прежней уверенностью. Пропуски из-за выключенного ПК и неполной истории видимы.

Политика хранения выбирается по конкретному поставщику и артефакту. Исключение прямого Blizzard API не доказывает бессрочные права на производные данные TSM/UE: остаются условия архива, передачи и повторного использования. Проект обязан применить подтверждённый срок, удалить соответствующие raw/derived данные и отметить утрату replay. Технический локальный TTL не является разрешением поставщика. Пять исследовательских CSV и их hashes сохранены приватно для воспроизводимой проверки; они не объявлены общедоступным архивом или массовой исторической базой.
