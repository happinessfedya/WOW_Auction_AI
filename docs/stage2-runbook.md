# Этап 2: запуск и независимая проверка

26.10.2026. Запускать из корня проекта в существующем `.venv`, Python 3.13.7,
SQLite 3.50.4, без установки новых пакетов. Сохранённый этап 1 работает отдельно.
Blizzard API и его ключи запрещены решением пользователя; их не нужно получать.

Исправленная ревизия после R1 описана в [ответе аудитору](review-responses/stage-2-r1-response.md).
При открытии старой market DB выполняется migration2→3; база активов не затрагивается.
`market-status` различает `cache_available` и `usable`, показывает source freshness
и политику возраста. Сохранённый файл/успешный HTTP сами по себе не означают
свежий рынок. Secret diagnostics сообщает `not_inspected` без чтения ключей.

## Настройка и команды

Уже создан `.private/market.local.json`: EU/Soulflayer, пять публичных наборов
TSM, Undermine отключён. База рынка `.private/market.sqlite3` отделена от базы
активов. Повторный `market-init` не перезаписывает существующую конфигурацию.
Для новой установки после настройки локального импорта этапа 1:

```powershell
.venv/Scripts/python.exe -B -m wow_auction market-init --region EU --realm-slug soulflayer
```

Доступные действия:

```powershell
.venv/Scripts/python.exe -B -m wow_auction market-status
.venv/Scripts/python.exe -B -m wow_auction market-scan
.venv/Scripts/python.exe -B -m wow_auction market-resolve
.venv/Scripts/python.exe -B -m wow_auction market-expire
```

`market-status` показывает происхождение, возраст, пригодность и состояние
загрузки. `market-scan` выполняет только наступившие задания; `--force` позволяет
однократную повторную проверку, но не отменяет 429/Retry-After/quota/lease.
`market-resolve` проверяет уже сохранённые свидетельства групп UE, без сети;
пока их нет, возвращает `undermine_membership_evidence_required`, exit 2.
Это не мешает TSM-импорту. `market-expire` применяет сроки хранения.

```powershell
.venv/Scripts/python.exe -B -m wow_auction market-watch --interval 10
```

Это отдельный foreground-процесс; остановка Ctrl+C. Проверка очереди раз в
10 секунд не означает загрузку каждого источника каждые 10 секунд: задания
TSM по умолчанию раз в 4 часа, учитываются cache-control и ограничения.
`--cycles 1` завершает один цикл. Автозапуск Windows и службы не установлены.
Игра может быть закрыта. Спящий/выключенный ПК не собирает рынок: gap фиксируется
при следующем выполнении. Без работающего процесса физическое удаление
просроченного кэша откладывается до следующего обслуживания, но истёкшее
содержимое уже не пригодно как рабочий вход.

## Источники и секреты

TSM не требует секретов. UE использует только собственный `undermine_api_key`
в `.private/market-secrets.local.json` либо `WOW_UNDERMINE_API_KEY`; наличие
ключа само по себе не снимает блокировку source policy. Сейчас сеть UE
заблокирована политикой `unresolved_api_terms_conflict`, поэтому менять
`enabled` недостаточно. Условия и пути разрешения описаны в [матрице](research/stage-2-no-blizzard-alternatives.md).
Нельзя обходить ограничения через чужой ключ, scraping интерфейса или Blizzard.
Платные методы дополнительно требуют `allow_paid_undermine`; автоматически они
не включаются. Значения ключей не печатаются и не входят в БД/отчёты/Git.

Старые Blizzard поля/переменные не читаются; включение `blizzard_api_enabled`
отклоняется. Даже программно переданный legacy job не вызывает Blizzard HTTP.
Чистый offline-парсер старого контракта оставлен для сохранения выполненной
работы, его сетевого маршрута нет.

## Повторение проверки

```powershell
.venv/Scripts/python.exe -B -m unittest discover -s tests -q
.venv/Scripts/python.exe -B -m wow_auction market-scan --force
```

Для требуемой повторной REAL-проверки без изменения рабочих баз:

```powershell
.venv/Scripts/python.exe -B tools/verify_stage2_market.py docs/stage2-new-live-check.json
```

Выберите ещё не существующее имя результата: прежние свидетельства не
перезаписываются. Скрипт использует настоящие публичные TSM GET, временную БД,
пять обычных и пять условных запросов; удаляет временную БД. Это не измерение
естественной cadence и не sleep/wake. На Windows standalone сетевые скрипты
должны иметь `if __name__ == '__main__':` для spawn; приведённый скрипт и CLI
это обеспечивают. Default transport ограничен общим deadline, включая DNS,
headers/body и передачу результата; предусмотрено bounded завершение процесса.

Первый прогон не обращается к сети/игре и использует SYN/MOCK. Второй читает
публичный TSM при доступной сети; фактический результат зависит от обновления
источника. Не требуется специально делать сделки в WoW или reload.
При неизменном содержимом и той же версии нормализатора 304/повторный hash
не омолаживает прежний снимок. Изменение нормализатора требует полного повторного
чтения и отдельной проекции; source scan time остаётся исходным.
При сетевой/схемной ошибке предыдущий пригодный снимок остаётся, health отражает
ошибку. Ноль minBuyout не бесплатная покупка, цена объявления не исполнение.

[REAL-результаты](stage2-live-evidence.json) содержат URL, статусы, hashes,
времена и размеры без исходного массива цен. Raw/нормализованные данные
ограничены retention; после удаления exact replay невозможен. SYN-тесты
повторяемы всегда, прежний REAL payload после удаления не восстановим по hash.
Manifest этапа 2 позволяет сверить исходники и отчёт; архив принятого этапа 1
доступен в `docs/research/baselines/stage-1-r2.zip`.
