## 1. Область и результат

Прочитаны основной промпт и все остальные пять документов `codex_handoff`, корневой README. Применён приоритет MAIN_CODEX_CORRECTION. В исходном репозитории был только README (baseline `13be866 first commit`) и неотслеживаемый handoff. Приложения для доработки не было; добавлена только документация и диагностические примеры внутри Markdown. Исходный пакет не изменён, коммит не создавался.

Три субагента независимо исследовали: локальные аддоны/данные; рынок/Blizzard; CraftSim/преобразования. Два выполнили дополнительную критическую вычитку экономики, третий — сверку общей спецификации с локальными фактами. Это внутренняя проверка качества, **не замена отдельного независимого приёмщика**.

После аудита R1 три субагента отдельно проработали S0-01 (широкое перечисление источников), S0-02 (жизненный цикл после продвижения), S0-03/05 (исторические режимы/знания LLM). Основной агент подготовил S0-04 и согласовал общие документы; дополнительные внутренние вычитки проверили новые контракты. Ни одна из этих работ не меняет официальный отрицательный вердикт R1.

Ключевые исправления R2: конкретный полный discovery traversal вместо sample batch; защитный монитор/пауза и согласованный переход с сохранением позиций после promotion; пять режимов временной оценки с запретом считать современную LLM на прошлом чистым прогнозом; открытое получение новых наблюдений/факторов со слепым тестом; отдельные publication bounds точной ревизии и конечных дневных агрегатов.

## 2. Предлагаемая архитектура

`Read-only источники → адаптеры → наблюдения/версии/карантин → независимые активы, рынок и база преобразований → детерминированная экономика → зафиксированный прогноз → отдельная виртуальная книга → аудит причин → теневые стратегии`.

Python-монолит с модульными контрактами, SQLite после проверки исправленного runtime, долговечный worker и локальный веб-интерфейс. FastAPI предложен с обоснованием; фреймворк не устанавливался. CraftSim остаётся расчётным движком, собственный будущий мост экспортирует параметры/результаты в свои SV. ИИ выбирается через заменяемый адаптер, не управляет игрой и не меняет hard constraints. Диаграмма и альтернативы: [architecture.md](architecture.md).

Проект экономической модели учитывает начальные запасы, перенос себестоимости, глубину предложения, залоги/возвраты, общие ресурсы и случайные ветви. Исполнение по снимкам не считается фактом. Причинный вывод и полезность прогнозного признака имеют разные статусы. Возможный итог расследования — unknown без изменения рабочей стратегии.

## 4. Главные риски и решения

1. **Фиктивная прибыль:** snapshot не подтверждает покупку/продажу. Отдельные conditional/unknown/scenario книги и baseline cash обязательны.
2. **Искажённый капитал/PnL:** дубли warband, stale контейнеры, TSM net price/округление/изменяемые строки. Нужны reconciliation и реальные контрольные события.
3. **Неполная механика:** CraftSim probability — модельная оценка; экспорт не полон, старые преобразования требуют проверки в текущем Retail. Unknown не заменяется выдуманной вероятностью.
4. **История и права:** найдено противоречие Blizzard TTL30d/длительный replay, нет универсального разрешения распространять TSM таблицы/данные. Политику хранения/seed надо подтвердить до соответствующей реализации.
5. **Ложная самокоррекция и ухудшение после допуска:** прибыльная новая модель не доказывает причину рынка. Нужны открытое обнаружение факторов, OOS/будущий shadow и монитор после promotion; при stop новые рисковые рекомендации приостанавливаются, старая версия проверяется заново, позиции/история не стираются.
6. **Runtime SQLite:** найден 3.50.4; документирован WAL-reset bug при определённой конкурентности. До WAL выбрать исправленный runtime; сейчас системные программы не обновлялись.

7. **Историческое знание:** available_at не фильтрует веса модели; новые LLM-прогоны старой истории исследовательские и исключены из валидных promotion metrics. Публичная реконструкция не меняет фактическое время получения; неизвестные publication bounds и daily finalization не замещаются догадками.

Все риски и трактовки X01–X12: [risks.md](risks.md). Никакие предложенные числа резерва/позиции/риска не утверждены молча.

## 5. Проверки и результаты

- Прочитаны TOC/конкретные Lua функции/ограниченные структуры реальных SV; в репозиторий не скопированы аккаунты, имена персонажей, суммы и сырые записи.
- Диагностический read-only разбор Ledger показал 6 семейств с **0 строками операций**. Это успешная проверка пустого состояния, не работающая интеграция торговли.
- Дополнительно проверен Auctionator341: posting history пуста; схема не содержит deposit/duration/outcome, поэтому пробел потерянных залогов не закрывает. Найденный отказ строгого UTF-8 не объявлен порчей файла, в будущий parser test добавлен encoding error.
- Реальные HTTP GET TSM дали **200**: 12162 commodity rows, 11027 realm rows, 31186 regional rows. Проверены заголовки/нули/timestamps/hashes. Повторный запрос после обновления может дать другие числа.
- UE без ключа **401**; Blizzard commodities без Bearer **404**, официальная документация **200**. Это транспорт/документы, не authenticated integration PASS.
- Выполнен код из [stage0-checks.md](research/stage0-checks.md): **PASS 13/13** синтетических арифметических/контрактных примеров. Он не проверяет приложение или игру.
- В R2 исходные13 примеров повторены; выполнены **18/18** дополнительных [контрпримеров R2](research/stage0-r2-checks.md). Это диагностические иллюстрации спецификации; будущие LC2/T2-A/слепой F2 тесты приложения не запускались.
- Реальные R2 пробы D2 установили перечисляемые source corpora/CSV и конкретные пробелы. Ledger/Auctionator probes повторены без изменений результата. Метаданные GX/BagSync/CraftSim совпали с более новым снимком аудитора; даты/хеши отдельно в local-addons §7. Рыночные HTTP результаты выше относятся к R1 и не выдаются за новый прогон.
- Внутренняя вычитка исправила формулировки initial NAV, cash/deposit, CostLot/conversion costs, Resourcefulness, неупреждающих ветвей, model estimates, unsupported-zero, времён и причинной идентификации. Неподтверждённые внешние проблемы сохранены отдельными рисками.
- Проверка исходного комплекта R1:8 обязательных документов/15 Markdown,53 локальные ссылки и22 hashes. Для текущего R2 выполняется расширенная проверка manifest/архива/ссылок/неизменности аудитора; результат фиксируется в ответе R2. Проверка секретных шаблонов ограничена и не является доказательством отсутствия любого возможного секрета. В docs по-прежнему нет приложения/БД; добавлен только архив исходных документов.
