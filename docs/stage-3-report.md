# Этап 3 — пакет для независимой проверки

26.10.2026. Этап разрешён пользователем после принятия подтверждённой части этапа 2 и переноса внешних проверок: [решение D2 и архив](stage-3-transition.md). Этапы 4–7 не начаты. Этот отчёт — свидетельство разработчика, не независимый вердикт и не утверждение полного покрытия игры.

## Результат

Реализованы отдельная база знаний, полный статический обход согласованного ATT Lua-корпуса, версии/возобновление/откат, обновления источника, автоматический импорт локальных CraftSim/TSM кэшей и собственный пассивный аддон. Ручное открытие рецепта или CraftSim Scan **не являются условием работы приложения**. Готовые расчёты открытого рецепта сохраняются дополнительно. Неполные сведения, предположения источника и подтверждённые наблюдения не смешаны.

Финальный обход `att-static-3`: **3470/3470 файлов** (включая все **1874** согласованных standard Lua), **141687 source candidates**. По статусам: **111225 candidate, 19664 historical, 10798 quarantined**. Все файлы имеют конечный disposition; неподдержанных файлов в финальной ревизии — 0. Неизвестная семантика отдельных выражений/ссылок остаётся. Это число утверждений источника с контекстом, не число уникальных игровых операций и не процент полноты WoW.

Первичный corpus commit `3d0461d9740940e09c9cb19390467ed6ec39cb9c`, текущий файл нормализации SHA-256 `121eff2aa99868d0ec41d6d9fc6dcf281ccf29cd10e824741124369cc3a064e2`. [Полный файловый manifest, coverage и ограничения](research/stage-3-corpus-evidence.md), [машинное свидетельство](research/stage-3-corpus-evidence.json). **453 Wago entries и 111 необходимых записей/индексов с неустановленным происхождением/правами остаются заблокированными**, ещё 3 generator sources и 3 заметки отмечены отдельно. В частности, itemDB.json/questDB.json нужны для более полного объединения данных; они не исключены из проектной области как ненужные. [Проверка их происхождения и зависимостей](research/stage-3-corpus-evidence.dependencies.json).

Полнота подтверждённых текущих механик не заявляется: автоматически promoted confirmed-current transformations — **0**. ATT collection relationship не превращается в гарантированный output, середина диапазона TSM не становится физическим выходом, а среднее CraftSim не становится joint PMF. Для надёжных рекомендаций ещё нужны механические доказательства и этап 4.

## Что работает автономно

`knowledge-watch` автоматически проверяет настроенные локальные файлы, импортирует новый собственный export и существующие кэши, определяет установленный Retail build, планирует недельные/патчевые обновления ATT. Полные исходные каталоги, обработка сохранённых сведений и рыночный worker этапа 2 работают при закрытой игре. Пассивный аддон самостоятельно обрабатывает известные recipe IDs в обычной игровой сессии, без открытия окон, сканирования профессии, создания предметов или автоматического reload. Выгрузку файла выполняет сам клиент при обычном сохранении.

В реальном локальном кэше уже доступны **57 TSM crafts**, **72 CraftSim item↔recipe mappings**, **75 recipeInfos (70 различных recipe IDs)**, **38 operationInfos**, **15 allocations** и метаданные предметов. Подтверждён импорт без новых игровых действий и без сети, повтор и перезапуск без дублей. [Отчёт автономности](research/stage-3-autonomy.md), [REAL input evidence](research/stage-3-autonomy.json).

Граница: cache facts и читающие игровые схемы **не являются новым полным персональным расчётом CraftSim**. Для его произвольного конструктора не найден подтверждённый полностью читающий batch-режим: есть зависимости от контекста WoW и обновление внутренних баз CraftSim. Текущие buffs/gear/качества и неизвестные исходы не восстанавливаются догадками. Открытый рецепт может дать дополнительный точный профиль, но его открытие не запрашивается как обязательный рабочий шаг. Этот технический пробел остаётся явным; программа продолжает доступную работу без него.

## Реальный CraftSim и выявленные исправления

Установлен только собственный `WowAuctionBridge`, исходные файлы других аддонов не правились. Первая версия была обнаружена клиентом после полного перезапуска WoW, что подтвердил пользователь. Пользователь выполнил обычные scan/reload; затем отказался от ручного выбора рецептов как зависимости продукта. Архитектура дополнена автоматическим локальным чтением и пассивным сбором; запрос ручной симуляции снят.

Текущая установленная версия — **0.3.2**, три файла собственной папки сверены с репозиторием. Предыдущие0.3.0/0.3.1 сохранены в приватных резервных копиях. Новый пассивный код начнёт исполняться при естественной следующей загрузке аддона. Вне игры уже выполнена проверка его Lua на реальном кэше:70/70 известных уникальных recipe IDs обработаны при намеренно недоступных игровых API, чужая таблица не изменилась, фиктивных engine profiles не создано. [Пассивная проверка](research/stage-3-craftsim-032-passive-evidence.json), [повтор расчётных Lua-сценариев](research/stage-3-craftsim-032-engine-evidence.json). Это не подменяет REAL запуск новой части внутри WoW.

- Первый REAL export: 7 записей, 4 `capture_failed`, 3 неполных/неподдержанных DTO. Точные причины старых четырёх ошибок установить нельзя: прежняя версия не сохраняла диагностику. [Первый capture](research/stage-3-craftsim-real-initial-evidence.json).
- Найден и воспроизведён отдельный дефект: лимит64KB отбрасывал обычный насыщенный профиль. Увеличен ограниченный бюджет, вложенные цены сведены к явным DTO, добавлены безопасные error code/section/recipe ID. Версия0.3.1 дала 2 новых реальных DTO без ошибок экспорта. [Второй capture](research/stage-3-craftsim-real-second-evidence.json).
- Реальная строка «Потенциал Света» выявила два дефекта Python: требование цены невыбранных optional reagents и неверное толкование `professionGearCached=true`. Исправлено по установленному исходнику, добавлены регрессии. Сохранённая стоимость согласуется с cheapest-quality fallback CraftSim; она не выдаётся за явно выбранные quantities/qualities.
- `capture_status` отделён от актуальности контекста персонажа. Сохранённые факты переживают reload как историческое наблюдение; это не доказывает неизменность текущих параметров. Старые неполные записи не переписаны задним числом.
- Собственный пассивный сбор — отдельный DTO, не фиктивный engine profile. Получение новых API-данных в настоящей сессии после загрузки пассивной версии и полная матрица изменений gear/spec/buffs/price/reagent/concentration пока не объявлены REAL PASS.

Точные версии, hashes, проверки установленного Lua и границы: [исследование CraftSim](research/stage-3-craftsim.md). C11 подтверждён выполнением установленного расчётного Lua на синтетических входах; порядок вычетов депозита сохраняется при узкой переоценке фиксированного варианта. Это не доказательство ошибки прибыли у пользователя. C21 `0,{}` не принимается автоматически за достоверную нулевую прибыль.

## Хранилище, обновления и проверки

`.private/knowledge.sqlite3` отделена от принятых книг активов/рынка: SQLite schema1, application ID `0x57414B33`, DELETE/FULL. Immutable evidence tables, полный manifest, checkpoint после каждой порции, проверка смены опубликованной версии при resume, исторический reappearance без скрытого rollback. Исправления фактов требуют текущих независимых upstream evidence и отдельно записанного решения проверяющего; их можно отменить без удаления истории. Платного исследователя здесь нет: AI-задания остаются в очереди до этапа 6.

При интеграции независимые субагенты воспроизвели и помогли исправить: старый pending import поверх нового, преждевременную видимость до availability, просроченную evidence при принятии correction, ошибочный lease DTO, дубли артефактов из-за receive-time, необработанный ошибочный Lua и потерю критических boolean flags. Отдельная semantic revision2 исключает координаты provenance из сравнения фактов; старые payloads пересчитываются для сравнения без изменения истории. Устаревшие задания сохранены как `superseded`, а не исполняются повторно.

В рабочей базе сохранены три реальные ревизии разработки. Финальная v3 добавила409 claims к предыдущей, остальные141278 не изменились. Повторный импорт не добавил строк. `quick_check=ok`, foreign-key errors=0; размер после трёх каталогов **1 224 720 384 bytes**, до последующих локальных артефактов. [Финальный импорт](stage3-v3-import-evidence.json). Предыдущие результаты сохранены: [v1](stage3-real-import-evidence.json), [v2](stage3-final-import-evidence.json). Полные immutable версии имеют заметную стоимость хранения; измерение трёх ревизий не является гарантией многолетнего объёма.

GitHub transport использует неизменённый проверенный механизм общего deadline этапа2 под отдельным строгим списком публичных ATT endpoints. Ключи, redirects и произвольные адреса запрещены. Каждый blob проверяется; новая ревизия переиспользует совпавшие файлы по Git hash, смена LICENSE останавливает загрузку до проверки policy. Проверен настоящий запрос LICENSE новым transport. Это не изменение принятого рыночного адаптера.

Команды воспроизведения, локальный polling и ограничения запуска — [runbook](stage3-runbook.md). Итоговый полный прогон и проверка состава пакета — [stage3-checks.json](stage3-checks.json). Пакет фиксируется [manifest](stage3-package-manifest.sha256); Git HEAD не заменяет его, поскольку проектные файлы остаются преимущественно untracked. Принятый этап2R2 сохранён в архиве до начала изменений.

Итоговый полный набор: **539/539 PASS, 23.940s, без SKIP** — 377 унаследованных тестов и162 новых. После автономной доработки отдельная проверка нашла crash на повреждённых вложенных полях passive DTO; добавлена полная проверка контейнеров и регрессия наблюдателя. Теперь такой источник возвращает `read_or_schema_error`, прежняя история сохраняется, обновления прочих источников продолжаются. [Совместимость финального parser с автономным Lua и настоящим кэшем](research/stage-3-craftsim-032-parser-guard-evidence.json).

Обычная команда `knowledge-watch --cycles 2 --interval 1` также выполнена на настоящих настроенных источниках: автоматически определён build12.1.5.70575, четыре вида локальных данных приняты, второй проход не создал дублей; сетевое обновление ещё не требовалось. Ручное открытие рецептов, scan и игровые команды этим запуском не выполнялись. [Итоговое свидетельство автономного запуска](stage3-autonomous-run-evidence.json).
