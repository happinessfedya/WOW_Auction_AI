## R2.6. Оставшиеся риски, ограничения и непроверенные возможности

1. **Полнота преобразований.** Доступные корпуса позволяют широкий перечислимый discovery; доказательства 100% экономических механик всей игры нет. ATT ориентирован на коллекции, server-side loot/PMF и полные BFA scrapping/Legion Obliterum yields остаются пробелами. Полный экспорт дополнительных DB2, artifact-specific права и запасной bulk источник ещё не подтверждены. Этап 3 обязан явно показывать coverage/gaps и не объявлять PARTIAL полным PASS.
2. **CraftSim.** Проверены исходники, не расчёт в запущенной игре. Профиль крафтера, готовность данных, проценты/совместные исходы, влияние C11, совместимость build и полнота будущего DTO требуют T3 runtime сравнения. Наличие API и SavedVariables этого не заменяет.
3. **Ledger и имущество.** Нет непустых реальных TSM событий и полной ручной сверки хранилищ. Не доказаны сопоставление одинаковых/изменённых строк, точность себестоимости и истинный PnL. Это будущие обязательные проверки, особенно T1-01/T1-07/T1-08/T1-09.
4. **Рыночные источники.** Успешные authenticated UE/Blizzard data calls в этом аудите не выполнялись, ключи не искались. R1-пробы публичных TSM CSV/401 сохраняются как исторические результаты; в R2 они не повторялись. Timezone/finalization/revision history UE нужно установить отдельно. Обход авторизации не предлагается.
5. **Исполнение и доходность.** Просмотренный рынок не доказывает покупки/продажи. Калибровка сценарных fill assumptions и фактическая прибыль отсутствуют. При остановке новой стратегии уже открытая неликвидная позиция может продолжать терять стоимость.
6. **Поиск причин.** Открытый контракт делает недостаточную реализацию проверяемой, но не гарантирует обнаружение произвольного неизвестного фактора. Наблюдательные данные могут не идентифицировать причину; plausible и unknown остаются законными итогами. Слепой F2 и реальные расследования пока не запускались.
7. **Новая стратегия может ухудшить результат.** OOS, shadow и probation не устраняют смену режима, множественный подбор, ошибку исполнения и случайность. Контроль SL2 ограничивает дальнейшее принятие риска и сохраняет историю; он не обещает возврата потерь. Численные пороги, окна, полномочия promotion/resume/rollback и риск-профиль ещё предстоит явно выбрать до соответствующих испытаний, а не после результатов.
8. **Реализация и временная чистота.** 31 синтетический пример не проверяет атомарность хранилища, изоляцию агентов, race/crash recovery, модельные веса или работу монитора. T2-A*, LC2-* и F2 — будущие критерии. Локальный hash не удостоверяет время против администратора ПК; удалённые по retention входы не восстанавливаются из хеша.
9. **Открытые решения.** Q01–Q13 остаются по стадиям: credentials/rights/retention, проверка владения и контейнеров, непустой Ledger, реальные CraftSim образцы, риск/AI budget и полномочия. Они не объявлены молча решёнными. Для этапа 0 внешней блокировки нет; отдельные последующие критерии без соответствующих данных будут BLOCKED, а не PASS.

## 2. Итоговый вердикт

**Этап 0 — НЕ ПРИНЯТ.**

Исследование содержит воспроизводимые факты и корректно обозначенные ограничения. Однако недостаточно спроектированы три существенные части: широкое первоначальное покрытие непрофессиональных преобразований, защита уже продвинутой стратегии от ухудшения и исторические испытания с облачным ИИ. | ID | Критичность | Статус R1 | Предмет |

### S0-01 — недостаточно обоснован путь к широкому покрытию непрофессиональных преобразований

**Доказательство.** [craft-transformations.md](../research/craft-transformations.md), строки 102–109, для контейнеров, item use, salvage/recycling/scrapping, NPC barter, currency purchases и periodic rewards/cooldowns предлагает отдельные `curated records`. Матрица строк 117–132 содержит повторяющиеся «то же» и «отдельный каталог». Пять конкретных примеров C22 в строках 88–96 не закрывают эти семейства. [acceptance-tests.md](../acceptance-tests.md), строка 58, T3-02 допускает «первичный подтверждённый batch каждой доступной семьи».

Проверенный первичный [README WoWDBDefs](https://github.com/wowdev/WoWDBDefs/blob/master/README.md) описывает определения форматов. Прочитанная [схема ItemExtendedCost](https://github.com/wowdev/WoWDBDefs/blob/master/definitions/ItemExtendedCost.dbd) описывает поля и версии структуры. Они не предоставляют готовый каталог содержимого контейнеров и ассортимента NPC.

**Как воспроизвести недостаток.** Для произвольной непрофессиональной семьи, например контейнеров старого дополнения, попытаться по проекту установить исходный перечисляемый набор и процедуру его полного обхода. Документы не дают этого маршрута. При этом небольшой набор известных примеров может удовлетворить T3-02.

**Фактическое / ожидаемое.** Обнаруженные пробелы честно названы, но их отображение не обеспечивает максимально широкого первичного наполнения. Ожидается проверяемый план перечисления кандидатов и граница покрытия каждого выбранного источника. Наличие полного реестра всей игры и полный импорт на этапе 0 не требуются.

**Причина и влияние.** Для части семейств конкретное исследование источников заменено названием будущей ручной работы; приёмочный критерий допускает слишком узкий результат.

**Необходимое исправление.** Таблица «семейство → конкретный источник → способ перечисления → поля → актуальность/права → ограничения → резервный маршрут». Небольшие безопасные пробы недостающих семейств, включая старый и современный контент. Для недоступных источников — точный блокер и непокрываемая область. T3-02 должен проверять завершение согласованных обходов источников, а не только наличие batch. Неизвестный глобальный знаменатель допустим; фиктивный процент полноты запрещён.

### S0-02 — откат заявлен, но поведение после продвижения не спроектировано

**Доказательство.** [economics-and-model-audit.md](../research/economics-and-model-audit.md), строки 67–69, описывает продвижение/отклонение/продолжение после испытаний. [data-model.md](../data-model.md), строка 43, перечисляет Promotion/Rollback. Q11 в [open-questions.md](../open-questions.md), строка 17, честно оставляет политику открытой. T6-06 в [acceptance-tests.md](../acceptance-tests.md), строка 101, проверяет отказ в продвижении при плохих held-out/future результатах. Обязательная реакция на ухудшение уже продвинутой версии не определена.

**Контрпример.** Кандидат успешно проходит историю и будущий shadow, становится основной версией; затем меняется рыночный режим. Из спецификации нельзя вывести обязательный переход состояния, остановку новых рекомендаций, порядок возврата к прежней версии и обращение с открытыми позициями.

**Фактическое / ожидаемое.** Есть сохранённая старая версия и упоминание отката. Нужен определённый протокол наблюдения и реакции после продвижения, сохраняющий согласованность портфеля.

**Причина и влияние.** Возможность восстановить конфигурацию не заменяет процедуру отката стратегии. Непродуманная смена версии может нарушить принадлежность позиций, резервов и себестоимости; прежняя версия также может оказаться непригодной после смены рынка.

**Необходимое исправление.** Описать жизненный цикл версии, наблюдение после продвижения, условия приостановки/отката и полномочия пользователя/автоматики. Определить сохранение истории, cost lots, резервов и обработки открытых позиций. Допустимые действия при отсутствии безопасной версии должны включать прекращение новых рекомендаций. Добавить сценарий «история и shadow успешны → после продвижения ухудшение». Численные пороги можно согласовать до будущего эксперимента; механизм реакции определить в этапе 0.

### S0-03 — временные фильтры не охватывают знания внутри облачного ИИ

**Доказательство.** [data-model.md](../data-model.md), строка 9; [economics-and-model-audit.md](../research/economics-and-model-audit.md), строки 49–51; T5-02 в [acceptance-tests.md](../acceptance-tests.md), строка 85. Ограничения охватывают входные записи, версии механик и будущие патчноуты. Нет контракта для будущих сведений в параметрах облачной модели или в её накопленном контексте. Фиксация model/prompt version в architecture не устраняет этот канал сама по себе.

**Контрпример.** Все переданные данные относятся к моменту до события, однако современная модель уже знает о последующем изменении игровой механики. Проверка available_at проходит, решение использует будущее. Это риск, а не установленная утечка конкретной ещё не выбранной модели WoW-проекта.

Первичное исследование [Look-Ahead-Bench](https://arxiv.org/abs/2601.13770) рассматривает отличие временно корректного прогнозирования LLM от результата, связанного с запоминанием. Оно подтверждает существенность класса риска; его результаты не являются измерением утечки в этом проекте.

**Фактическое / ожидаемое.** Заявлен строгий запрет look-ahead, но доступность явно переданных данных приравнена к полноте доступной модели информации. Нужны отдельные допустимые режимы и ограничения заявлений об их результатах.

**Причина и влияние.** Не учтён канал знания, не проходящий через таблицу наблюдений. Историческая оценка ИИ способна получить незаслуженный статус проверки без подсматривания.

**Необходимое исправление.** Разделить точный replay ранее сохранённых решений, исследовательский исторический прогон современной модели и настоящую перспективную проверку. При неподтверждённой временной чистоте модели не маркировать её исторический результат как строгий point-in-time тест. Изолировать прогнозирование от последующего расследования; сохранять версии, контекст, входы/выходы. Добавить отрицательный сценарий утечки. Инструкция в prompt «не используй будущее» не является достаточным доказательством защиты. Обучать собственную модель для приёмки этапа 0 не требуется.

### S0-04 — тесты не отличают открытие нового фактора от перебора известных причин

**Доказательство.** [economics-and-model-audit.md](../research/economics-and-model-audit.md), строки 73–84; [acceptance-tests.md](../acceptance-tests.md), строки 96–99. Сценарии заранее называют календарь, предложение, тренд, случайность и другие объяснения. Общий контур расследования есть, но отсутствует критерий расширения первоначально неполного набора факторов.

**Контрпример.** Реализация с закрытым списком причин и выбором одной из заранее перечисленных альтернатив может пройти эти критерии, не умея регистрировать и проверять новый фактор.

**Фактическое / ожидаемое.** Описан анализ модельных ошибок. Ожидается проверяемый путь от необъяснённого отклонения к запросу новых наблюдений и проверке ранее отсутствовавшего измеримого фактора либо к обоснованному unknown.

**Причина и влияние.** Центральное требование неизвестных ранее факторов не превращено в различающий критерий приёмки. Вместо требуемой функции можно принять классификатор известных ошибок.

**Необходимое исправление.** Описать путь «необъяснённое отклонение → недостающие наблюдения → новый фактор-кандидат → доступность во времени → эксперимент». Добавить слепой синтетический сценарий: причина отсутствует в исходном наборе факторов и не сообщается исследующему агенту. Если свидетельств нет, корректный результат — unknown без изменения основной стратегии. Сейчас требуется описание будущей проверки, а не реализация исследовательского агента.

### S0-05 — точный replay и историческая реконструкция имеют неоднозначный контракт

**Доказательство.** [data-model.md](../data-model.md), строка 9: available_at — время принятия записи приложением; в backtest требуется available_at <= decision_at, одновременно упомянута реконструированная доступность. [architecture.md](../architecture.md), строка 81, правильно запрещает выдавать поздний backfill за известный приложению ранее. Правила отдельного реконструируемого режима и допуска его входов не определены.

**Контрпример.** Наблюдение опубликовано 1 октября, впервые загружено приложением 26 октября, историческое решение моделируется на 2 октября. Строгий фильтр исключает запись. Подмена available_at датой публикации искажает происхождение. В независимой арифметической проверке: event_at=100, public_available_at=105, available_at=300, decision_at=110; текущий фильтр даёт False, фильтр публичной доступности — True. Это демонстрация различия режимов, не тест приложения и не утверждение доказанной даты публикации реальных данных.

**Фактическое / ожидаемое.** Реконструированная доступность упомянута, но отсутствует проверяемое правило. Ожидаются разные режимы с неизменным фактическим временем получения и явным основанием реконструкции.

**Причина и влияние.** Время знания приложения и реконструируемая доступность публичной информации недостаточно разведены. Реализация вынуждена сама выбрать между исключением всей поздно полученной истории и недостоверным переносом времени знания назад.

**Необходимое исправление.** Отдельно определить точный replay и условный исторический backtest. Для реконструкции хранить основание предполагаемой доступности, задержку публикации и неизвестность. Добавить проверки backfill и дневных агрегатов: по [официальной документации Undermine](https://undermine.exchange/api.html) дневная точка соответствует максимальному количеству за день и не становится известной в начале этого дня.

## 5. Экономические и модельные риски отдельно от технических дефектов

1. Успешные исторические и перспективные испытания не гарантируют будущего улучшения. Возможны смена режима, случайный успех, перебор вариантов и ошибка модели исполнения. Требуются ограничения риска и реакция после продвижения; это основание S0-02, а не утверждение о фактически убыточной стратегии.
2. Одинаковый симулятор обеспечивает сопоставимость стратегий, но не доказывает правильность симулятора. Условная прибыль остаётся условной, даже если её диапазон выглядит консервативным.
3. По снимкам нельзя однозначно восстановить спрос и продажи. Уменьшение количества допускает продажи, отмены и истечение; часть причин останется unknown. Источник дополнительных подтверждений должен быть независим по происхождению, а не только по домену сайта.
4. Полезность нового признака для прогноза не доказывает его причинное влияние. Проверенные документы это корректно разделяют; самостоятельного дефекта подмены причинности рассказом ИИ не обнаружено.
5. Источники CraftSim/TSM содержат модельные коэффициенты, которые нельзя автоматически объявлять эмпирическим полным распределением игровых исходов. Проект это признаёт. Сомнение C11 о депозите не воспроизведено в игре и не повышено аудитором до доказанного runtime-дефекта стороннего аддона.

Ни прибыльность, ни причинность реального рыночного события в этой проверке не устанавливались. Перечисленные альтернативы — риски/контрпримеры, а не диагнозы экономических потерь пользователя.

### Manifest, ссылки и три диагностических блока

Приведённый ниже код объединяет выполненные read-only проверки. Перед запуском Python-блоков из Markdown следует убедиться, что их содержание соответствует проверенному manifest и остаётся безопасным. Это диагностические блоки исследовательских документов, не тесты приложения.

```powershell

from pathlib import Path
import hashlib, re, subprocess
root = Path.cwd()
manifest = root / 'docs/research/package-manifest.sha256'
count = 0
for line in manifest.read_text('utf-8-sig').splitlines():
    m = re.match(r'([0-9a-fA-F]{64})\s+\*?(.+)', line)
    if not m:
        continue
    p = root / m[2]
    assert p.is_file() and hashlib.sha256(p.read_bytes()).hexdigest() == m[1].lower(), m[2]
    count += 1
print('manifest PASS', count)
docs = [p for p in (root / 'docs').rglob('*.md')
        if 'reviews' not in p.relative_to(root / 'docs').parts]
links = 0
for p in docs:
    for target in re.findall(r'\[[^\]]*\]\(([^)]+)\)', p.read_text('utf-8-sig')):
        if re.match(r'https?://|#', target):
            continue
        assert (p.parent / target.split('#')[0]).exists(), (p.name, target)
        links += 1
print('developer Markdown files', len(docs), 'valid local links', links)
for name in ['stage0-checks.md', 'local-addons.md', 'addon-inventory.md']:
    txt = (root / 'docs/research' / name).read_text('utf-8-sig')
    for i, code in enumerate(re.findall(r'```python\r?\n(.*?)\r?\n```', txt, re.S), 1):
        print('RUN', name, i, flush=True)
        result = subprocess.run(['python', '-'], input=code, text=True, capture_output=True)
        print('exit', result.returncode)
        print(result.stdout)
        assert result.returncode == 0, 'Diagnostic failed; inspect locally without exposing private values'
'@ | python -
```
